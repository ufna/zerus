# Zerus — живучие tmux-сессии агентов между машинами

`hgs` запускает команду (Claude Code, Codex, Kimi, шелл, что угодно) в **именованной
tmux-сессии проекта** и подцепляется к ней — локально или на другой машине по ssh.
Сессия живёт, пока жив бокс: закрыл вкладку, упал ssh, ноут ушёл в сон — агент на месте.
Для перезагрузки есть `pause`/`resume`: hgs сохраняет точный ID беседы агента на диск.
tmux здесь невидимый демон: ни окон, ни панелей; вкладки и сплиты — дело эмулятора.

```
hgs claude sample-project           # есть сессия -> attach; нет -> новая беседа claude
hgs @mac claude foo              # то же самое на другой машине (ssh под капотом)
hgs ls                           # сессии здесь и на пирах
hgs a claude/sample-project/review  # attach по полному имени
hgs kill claude/sample-project
hgs pause --all                   # остановить подтверждённые, простаивающие сессии
hgs resume --all                  # после перезагрузки восстановить их в фоне
hgs project ls                   # локальные псевдонимы папок для CLI (совместимость)
hgs claude sample-project -c        # продолжить последнюю беседу каталога
hgs --dry-run claude sample-project # напечатать tmux/ssh-команду вместо запуска
```

Полная шпаргалка и правила — `hgs -h`.

## hgs zerus — менеджер сессий

**Open hgs** в трее или ЛКМ по иконке открывает список сессий в hgs zerus на Linux и macOS. Из командной строки:
`hgs-tray --sessions` (на Mac — `~/Applications/hgs-tray.app/Contents/MacOS/hgs-tray --sessions`).
Версия приложения видна внизу полосы навигации и в Settings; заголовок окна — `hgs zerus`.
Повторный вызов поднимает уже открытое окно. Закрытие окна оставляет трей и агентов работать.

- В трее видны **два числа**: сверху — все сессии, снизу — **Needs attention**
  (ожидание ввода, разрешения, ошибка или непросмотренный ответ). Нижний счётчик выделен янтарным фоном,
  когда он больше нуля; ноль остаётся видимым на нейтральной подложке. Недоступные
  машины сохраняют общее число сессий по последнему снимку, но не увеличивают
  счётчик внимания; точка на иконке означает неполные данные.
- При переходе в **Needs attention** появляется системное уведомление. Клик открывает
  **Activity** именно этой сессии в Zerus, включая удалённые и переименованные сессии.
  Повторные опросы и перезапуск приложения не повторяют тот же запрос; после решения
  уведомление удаляется. Новые ответы основного агента и явные запросы сабагентов
  также вызывают уведомление; обычные результаты и ошибки сабагентов остаются у
  основного агента. При ошибке доставки Zerus показывает причину и повторяет попытку
  через минуту, если повод для уведомления ещё актуален.
  На Mac используется Notification Center от имени hgs zerus:
  при первом запросе нужно разрешить уведомления в системном диалоге. Настройки Focus /
  «Не беспокоить» и запрет уведомлений ОС продолжают действовать.

- Узкая полоса навигации (56 px): сессии, проекты, машины, настройки. Поиск и
  фильтры-иконки со счётчиками находятся над списком сессий. Выбранную машину видно
  в отдельном компактном фильтре; нажатие на него возвращает все машины.
- **Проекты сессий** управляются в отдельном разделе **Projects** на левой панели.
  Перетащите сессию на заголовок проекта или между его сессиями; перетаскивание
  заголовка меняет порядок проектов. ПКМ позволяет перемещать сессии и настраивать
  проекты. В одном проекте можно собрать папки и сессии с разных машин.
  **Settings → Hide projects without active sessions** по умолчанию скрывает в списке
  проекты без неархивных сессий. Готовые, сохранённые и недоступные на другой машине
  сессии продолжают учитываться. В **Archive** видны проекты с архивными сессиями,
  а в **Projects → All swarm projects** доступен полный общий каталог. Проекты можно раскрывать и сворачивать по отдельности
  или все сразу; янтарный бейдж показывает запросы ответа, голубой — непросмотренные
  результаты, зелёный — работающих.
  Поиск открывает отдельный список совпадений. Сворачивание сохраняет выбранную рабочую панель,
  а переход из уведомления раскрывает нужный проект. Проекты синхронизируются между
  участниками роя; ручной порядок и свёрнутость сохраняются локально. Пауза, возобновление,
  недоступность машины и переименование отслеживаемой сессии не сбрасывают размещение.
- Плюс **New session** на левой панели открывает диалог новой сессии.
  После отправки команды сразу появляется строка **Starting…** в выбранном проекте.
  Она заменяется реальной сессией по идентификатору запуска, включая удалённые машины.
  Пока запуск не подтверждён, команды управления сессией недоступны; после длительного
  ожидания строка предлагает проверить терминал. Ошибка открытия терминала или запуска
  DeepSeek снимает временную строку и выводит причину в статусной панели.
  ПКМ → **Hide launch status** скрывает ожидание, сохраняя назначение проекта при позднем
  появлении сессии. Старые незавершённые запросы предыдущих версий не появляются как новые запуски.
- Шапка сессии занимает две строки: имя, состояние и кнопки действий, затем машина,
  агент, Git-контекст, модель и effort. Полный путь доступен в **Details** и подсказках.
  **Settings** — обычный экран с разделами Appearance, Sessions, Automatic recovery и About; кнопка остаётся внизу левой панели. Тема и плотность списка сохраняются на этом устройстве.
  **Settings → Automatic recovery** задаёт общие для Zerus правила реакции на временную перегрузку сервера,
  ограничение частоты запросов и сетевые ошибки. Открытый Zerus синхронизирует версии правил
  между доступными машинами каждые 15 секунд через HGS/SSH; отключённые машины догоняют
  после подключения. Без GUI исполнители продолжают использовать сохранённые локальные копии.
  Ревизия и идентификатор изменения обеспечивают сходимость при одновременном редактировании;
  сохранение устаревшей формы требует Reload. Внешнего облачного сервиса нет.
  По умолчанию автоматизация выключена. У каждого класса свой список задержек:
  `15, 30, 60, 300, -1` останавливается после четырёх попыток;
  `15, 30, 60, 0` после первых двух повторяет задержку 60 секунд без ограничения числа попыток.
  `-1` без задержек означает ничего не делать. В задержки добавляется небольшой разброс.
  Счётчики отдельных классов сохраняются при смене типа ошибки внутри одной цепочки.
  Claude, Codex и Kimi получают явно помеченное сообщение `[HGS automatic recovery]`
  с просьбой продолжить текущую задачу в той же беседе. Исходный запрос и команды
  инструментов HGS не повторяет. DeepSeek через новый адаптер повторяет неудачный
  запрос модели; уже запущенный старый host использует сообщение продолжения.
  Учётные данные, баланс, квота и переполнение контекста требуют ручного действия.
  Сначала завершаются собственные повторы агента. Новый ввод, вопросы, остановка
  сессии или смена идентичности отменяют ожидание; черновик в Terminal блокирует ввод.
  В Activity видны отсчёт, номер попытки, история Attempts, Retry now и Cancel retry. Retry now соблюдает
  известный срок Retry-After. Настройка применяется к новым сбоям; уже запланированная
  цепочка сохраняет свои задержки. Выключение отменяет автоматические продолжения.
  Состояние хранится на хосте в `sessions/recovery/`, с проверкой ревизии настроек,
  блокировкой единственного исполнителя и квитанциями. Неясная доставка останавливает
  цепочку: второй Enter автоматически не отправляется. `install.sh` устанавливает
  пользовательский `hgs-recovery.service` / `com.hgdev.hgs-recovery`, независимый от GUI.
  Для нестандартной установки без сервисов доступен `hgs recovery worker`; CLI:
  `hgs [@host] recovery get`, `set`, `sync` и `action` (запись JSON через stdin).
  Новые провайдеры подключаются явно через реестр адаптеров в `src/state/recovery.rs`;
  неизвестный агент не получает автоматический ввод.

  В Activity кнопка **Stop** прерывает текущий ход (Escape для Claude/Codex/Kimi,
  нативный cancel для нового DeepSeek host) и отменяет recovery, сохраняя сессию.
  Очередь следует нативному поведению агента: Escape в Codex может запустить queued follow-up.
  Выполняемый ход проверяется перед отправкой; неопределённая доставка не повторяется автоматически.
  При открытой вкладке **Terminal** drop вставляет пути без Enter; для удалённой сессии
  файлы сначала копируются на её машину (до 8 файлов, 10 MiB каждый, 20 MiB суммарно).
  Смена вкладки, сессии или подключения во время переноса отменяет вставку.

  Вопросы имеют **Back / Next**, а последний шаг — **Submit answers**. Для распознанного
  Bash approval Claude и нативного DeepSeek доступны **Approve once / Deny**.
  Approve открывается после трёх секунд просмотра в активном окне; обновление команды
  сбрасывает отсчёт. Постоянные разрешения и смена permission mode этой кнопкой не выбираются.
  Неизвестная или неполностью видимая форма остаётся доступной через Terminal.

  Лимиты учёток на Dashboard и в нижней панели окрашиваются по использованной доле;
  для исчерпанного окна показывается время до сброса, а в Activity — предупреждение.
  **Cache** рядом с контекстом показывает оценку TTL из нативных usage-данных Claude
  (5m / 1h), не продлевая её при повторном чтении одного ответа. Изменение prompt, модели
  или инструментов может сбросить кеш раньше. Нативное `uncached` Claude и cache chooser
  Kimi показываются как холодный кеш; предложение `/clear to save…` само по себе этого
  не означает. Перед отправкой из Activity в холодную сессию требуется явное продолжение.
  При неизвестном состоянии индикатор кеша скрыт: кеш предыдущего запроса
  не доказывает его сохранность сейчас. `/clear` автоматически не вызывается.
  Постоянная кнопка **Clear session** находится в **Details** рядом с показателем
  контекста и доступна также при открытой вкладке Terminal. Перед очисткой нужен
  явный ответ в **Clear session?** с именем сессии и машины; **Cancel** выбран по
  умолчанию, Esc отменяет действие. Смена запуска или беседы во время диалога
  отменяет отправку команды. Неотправленный черновик сохраняется.
  **Clear context** вызывает нативный `/clear` в текущем Claude, Codex или Kimi,
  без диалога создания сессии. Черновик Zerus сохраняется. Команда доступна только
  для свободного агента и пустой строки ввода в терминале; повторная отправка
  неподтверждённой команды блокируется. DeepSeek пока не предоставляет такой
  нативный сброс через свой API. В предупреждении перед отправкой можно выбрать
  **Send with full context**, **Compact and continue**, **Clear context** или **Cancel**.
  **Compact and continue** запускает нативный `/compact` у Claude, Codex, Kimi
  и DeepSeek, затем отправляет сохранённый черновик после подтверждения успешного
  сжатия. Сжатие сохраняет резюме вместо полной истории и само расходует токены.
  Ошибка, отмена, отсутствие полезной истории, изменение черновика или разговора
  оставляют текст без отправки. **Cancel pending send** отменяет ожидающую отправку;
  **Stop** прерывает работу агента. Старый уже запущенный хост DeepSeek не объявляет
  новую возможность: она появится после его следующего запуска с обновлённым адаптером.
  Индикатор compaction находится в общей строке с кешем и объёмом контекста.
  После входа в аккаунт Zerus перечитывает его идентичность при изменении данных
  авторизации, не ожидая пятиминутного обновления лимитов; совпавшие учётки
  на разных машинах объединяются по проверенной идентичности провайдера.

- Компактный список сессий: имя, проект, ветка Git или linked worktree, машина,
  значок агента, текущее действие, модель и effort. Полные значения доступны в подсказках.
  Статус показан цветной плашкой рядом с именем. Ожидание ввода или разрешения
  выделено жёлтым, ошибки — красным; тонкая полоска слева помогает найти эти строки.
  Выбор обозначается нейтральным фоном и рамкой независимо от состояния.
  Рабочая папка и Git определяются на машине сессии, в том числе для старых
  tmux-сессий без отслеживания хуков. Папки вне Git остаются обычными папками.
- Сессии всех машин, поиск по имени, папке, модели, ветке и содержимому, фильтры **Needs attention**, **Working**,
  **Saved sessions**, отдельный **Archive** и выбор машины. При потере связи сохраняется последний снимок.
- В карточке: текущий инструмент, модель, последний запрос и ответ, журнал событий,
  субагенты и точный ID беседы. **Ready** означает конец ответа, а не завершение задачи.
  Ответы Kimi и промежуточные сообщения между инструментами дополнительно читаются
  из журнала выбранной беседы, поскольку хук Stop может не содержать текста.
  В Activity попадает публичный текст с исходным временем появления;
  служебные блоки рассуждений не отображаются. Читается ограниченный хвост журнала
  (до 8 MiB, до 50 ответов, до 32 тысяч символов на ответ).
- Счётчик субагентов показывает наблюдаемую активность прямо в строке сессии;
  Правая панель **Tasks & agents** раскрывает доступные задачи и последние действия. Это состояния
  из событий агента, а не оценка процента выполнения задачи. Если событий нет,
  интерфейс сообщает об отсутствии данных.
- **Ctrl/⌘ + клик** добавляет сессию в выделение или снимает её. Открытый разговор
  и черновик остаются на месте; опрос сохраняет выделенные сессии по их идентичности.
  Снизу списка появляется панель групповых команд: прочитано/посмотреть позже,
  пауза, возобновление, архив, перенос в проект, завершение и удаление записей.
  Подсказка и меню показывают, к скольким выбранным сессиям применима команда.
  ПКМ при множественном выделении открывает только групповые действия.
  Крестик или **Esc** снимает всё выделение. Сабагенты и заголовки проектов в него не входят.
- **Clear archive…** в меню списка сессий доступна при любом фильтре
  и удаляет архивные записи на выбранных машинах.
  Подтверждение показывает количество и список; офлайн-записи остаются.
  Очистка использует точные ID, не затрагивает живые сессии и новые записи,
  появившиеся после открытия подтверждения. Родная история агентов сохраняется.
- **ПКМ по сессии** (или `Shift+F10` / клавиша Menu) открывает её контекстное меню:
  открыть терминал, скопировать команду, переименовать, поставить на паузу или
  восстановить, перенести в архив, забыть запись либо завершить работающую сессию.
  Там же можно скопировать имя и путь к папке. Доступность действий зависит от
  состояния сессии; копирование работает и для недоступной машины.
  **Copy restore command** для Archive включает ID выбранной архивной записи.
  Явное **Open terminal** открывает терминал и при режиме `clipboard`, не меняя
  выбранный режим по умолчанию. ПКМ по пустому месту меню не вызывает.
- Открытие сессии следует настройке **Open in** трея; **Pause session** доступна
  после завершения ответа и субагентов; **Resume session** возвращает сохранённый контекст.
  Завершённые беседы в **Archive** возвращаются только кнопкой **Restore**; Enter не запускает их.
  **New session** предлагает проект, компьютер, рабочую папку и агента.
  По умолчанию агент запускается в фоне. **Open terminal window** дополнительно открывает
  внешний терминал; последний выбор сохраняется независимо от режима `clipboard`.
  **Browse…** показывает каталоги выбранной машины, в том числе удалённой; доступны
  переход вверх, домашняя папка, ввод пути, фильтр и скрытые папки.
- Имя новой сессии предлагается автоматически (`work-xxxxxxxx`), его можно изменить.
  Новая сессия всегда получает отдельное имя: например, `codex/my-project/work-a3b8c912`.
  Существующее живое или сохранённое имя не переиспользуется. Папки проекта
  настраиваются в разделе Projects.
- **Actions → машина → Pause all / Resume all in background** управляет всеми сессиями
  выбранной машины. Архив в массовом восстановлении не участвует.
  Пауза доступна, когда все живые сессии готовы и их контекст отслеживается.
- **Projects** в боковой панели управляет логическими проектами, их цветами
  и папками на всех подключённых машинах.
  **Open folder** открывает локальную папку в файловом менеджере. По ПКМ доступны
  открытие, копирование пути, добавление, изменение и удаление папки из проекта.
- Светлая и тёмная темы следуют системе. Поиск — `Ctrl/⌘ F`, обновление — `Ctrl/⌘ R`,
  открытие выбранной сессии — `Enter`, закрытие окна — `Esc`.

Панель получает события из хуков Claude Code, Codex и Kimi Code; это не поток полного
чата или рассуждений. Сессии, созданные до установки отслеживания, показываются как
**Not tracked**: их терминал доступен, но внутреннее состояние неизвестно.
Состав событий зависит от агента; новые регистрации хуков применяются при запуске через hgs.
В частности, Kimi 2.1.1 не передаёт текст ответа в `Stop`: Zerus дополняет Activity
ответами и промежуточными сообщениями из `agents/main/wire.jsonl` именно этой беседы.
Промежуточный текст появляется во время работы; поздние копии сообщений в журнале
не создают повторных карточек.

Если Kimi сообщает только профиль субагента, zerus показывает **Profile groups**:
число наблюдаемых запусков и ещё работающих участников этого профиля. Индивидуальные
ID и соответствие ответа конкретному участнику в таком случае неизвестны.
Для старого Swarm, который уже работал до появления этого учёта, точное количество
задним числом восстановить нельзя: счётчик отмечается как неполный. **Ready** у
субагента означает завершённый ответ, а не окончательное выполнение всей задачи.
Старые сведения для Offline, Saved и Archive показываются как последние записанные.

Для внешних клиентов доступны:

```bash
hgs ls --json --local                         # краткие состояния всех сессий
hgs inspect codex/hgs/review                  # состояние и последние 100 событий
hgs inspect codex/hgs/review --after 123       # до 200 событий после cursor
hgs @mac inspect claude/sample-project           # тот же API через SSH
hgs @mac dirs '~'                            # домашняя папка на Mac
```

Для нового запуска из папки в CLI: `hgs codex /path/to/folder --new`,
на другой машине — `hgs @mac codex '/Users/example/work/project' --new`.
`--new` генерирует имя автоматически; `--new -n review` использует заданное имя
и откажет, если оно уже занято. Для просмотра удалённой домашней папки используй
`hgs @mac dirs '~'`; `hgs dirs --hidden /path` включает скрытые каталоги.

`inspect` возвращает `conversation_id`, `phase`, `activity`, `prompt`, `last_message`,
`active_tools`, `subagents`, `events` и `cursor`. `phase` различает работу, инструмент,
ожидание разрешения/ввода, сжатие контекста, простой, ошибку и прерывание.
При смене `conversation_id` клиент сбрасывает курсор. `history_truncated` сообщает
о пропуске из-за ограничения размера журнала. Для сессии без привязки возвращается `tracked: false`.

Для отправки сообщения внешним клиентом есть `hgs [@host] send <session> --json`.
JSON передаётся через stdin: `request_id` (UUID), `text`, `expected_run_id`,
`expected_conversation_id` и `attachments` (массив `{name, mime, data_base64, reference?}`).
Необязательный `reference` — уникальный ярлык `[Image #1]` или `[File #2]` в тексте:
вложение передаётся на месте первого такого ярлыка. Без ярлыка файл добавляется в конец.
Идентификаторы берутся из свежего `inspect`. Ответ `status: submitted` подтверждает
передачу в терминал, а не ответ модели. Квитанция сохраняется по `request_id`:
повтор того же запроса не отправляет сообщение второй раз. Неопределённая доставка
требует проверки терминала перед новым запросом.

`ls --json` и `inspect` также возвращают `cwd`, `cwd_source`, `git_root`, `git_branch`,
`cwd_canonical`, `git_common_dir`, `git_worktree`, `git_worktree_name`, `git_detached` и `git_metadata_state`.
Git-метаданные кешируются на 15 секунд; их чтение ограничено по времени и не влияет
на разрешение паузы или восстановление контекста.
Текущее действие находится в `activity_summary` / `activity_detail`.
Поля `subagent_active_count`, `subagent_completed_count`, `subagent_total_count`,
`subagent_counts_complete` и `subagent_source` описывают полноту счётчика;
неизвестное количество обозначается `null`. `subagent_previews` содержит до шести
активных или непроверенных записей. Полный доступный список `subagents` с
индивидуальными ID также входит в список сессий; профили без ID остаются
в `subagent_groups`. Стрелка у сессии раскрывает дочерние Activity.
Непрочитанные ответы детей отмечают родителя; Mark all as read сбрасывает их.
У официального DSH продолжимые (`continuable`) дети принимают сообщения через
родное API с проверкой родителя. Остальные адаптеры и одноразовые дети доступны
для чтения истории. Поле `agent_id` в `hgs send` поддерживается только для DSH.

Журнал `events.sqlite3` лежит рядом с записями сессий на машине агента, доступен только
владельцу и ограничен примерно 50 тысячами событий на машину. Он хранит короткие
фрагменты запросов, команд инструментов и ответов; они могут содержать данные проекта.
Полная история остаётся у самого агента. После паузы/восстановления журнал продолжается
для той же беседы. Пока окно открыто, выбранная сессия опрашивается каждые 2,5 секунды,
списки машин — каждые 5 секунд; при закрытии остаётся обычный фоновый опрос трея.

## Пауза и восстановление после перезагрузки

```bash
hgs pause claude/sample-project/review
hgs pause --all
# Перезагрузка машины, на которой работают агенты.
hgs ls                           # сохранённые сессии остаются в списке
hgs resume claude/sample-project/review    # восстановить беседу и подключиться
hgs resume --all                  # восстановить сохранённые сессии без подключения
hgs a claude/sample-project/review    # тоже умеет восстановить сохранённую сессию
hgs @mac pause --all              # команды работают и на пирах
```

Можно продолжить беседу по её родному ID, даже если она запускалась без hgs:

```bash
hgs codex -c 01a0e955-b037-73f0-bc6c-36622a8c27b7
hgs codex /path/to/project --resume=01a0e955-b037-73f0-bc6c-36622a8c27b7 -n review
```

`-c` без ID сохраняет прежнее значение: продолжить последнюю беседу проекта.
После `-c` ID распознаётся как UUID; для Kimi также принимается `session_<UUID>`.
При явном ID hgs запускает только указанную беседу, без перехода к последней или новой
при ошибке. Уже отслеживаемая беседа открывается под своим именем; для остальных
создаётся имя `resume-<ID>`, если не задано `-n`. Занятое имя с другой беседой
вызывает ошибку. История должна находиться на машине, указанной в команде.

Если запуск прервался до подтверждения беседы — например, отменён запрос пароля
в проектном `run_codex.sh` — повторите ту же команду. Такая остановленная попытка
не является Saved-сессией и не требует `--fresh`. Перед повторным запуском её
диагностическая запись сохраняется в `attempts/` внутри каталога состояния hgs;
история агента не удаляется. Уже подтверждённые беседы сохраняют точное восстановление.

В hgs zerus сессию можно переименовать через **⋯ → Rename…** в её карточке.
Редактируется метка после имени проекта; агент и рабочая папка остаются прежними.
Переименование работает для запущенных и сохранённых сессий, в том числе на другой
машине. Агент продолжает работать в том же процессе, а открытые терминалы получают
новый заголовок. Отслеживание и история событий переходят на новое имя.

```bash
hgs rename codex/project-docs/review codex/project-docs/fight-db
hgs @mac rename claude/sample-project/review claude/sample-project/deploy
hgs rename codex/project-docs/review codex/project-docs/fight-db --archive <id>
```

Для Archive меняется только выбранная архивная запись. Имя запущенной или Saved-сессии
должно быть свободным; архивные записи могут иметь одинаковые имена. Метка допускает
Unicode и пробелы внутри, но не `/`, `:`, `.`, управляющие символы или пробелы по краям.
`--dry-run` проверяет операцию без изменения состояния. `HGS_TAB=0` отключает обновление
заголовков терминала. Для вкладок с вручную закреплённым названием терминал может
потребовать включить показ заголовка приложения.

Поддерживаются **Claude Code, Codex и Kimi Code**. Начиная с hgs 1.11 CLI и ядро
сессий написаны на **Rust**: установленный `hgs` — нативный исполняемый файл.
Для сборки нужны Rust/Cargo 1.85+ и C-компилятор (SQLite включается в бинарь),
для работы — tmux, SSH и нужный агент. Qt-приложение hgs zerus остаётся отдельным клиентом.

Новые хуки вызывают `hgs __state hook` и не требуют Python. Уже установленные и
доверенные команды хуков не переписываются: `hgs_state.py` остаётся небольшим
переходником, который передаёт старый вызов в Rust. Для этих старых хуков нужно
сохранить имеющийся Python; Python-реализации управления сессиями больше нет.
Формат сохранённых привязок, история агентов и курсоры журнала совместимы с hgs 1.8–1.10.

При первом запуске агента hgs добавляет свои обработчики событий в его пользовательский
конфиг: Claude — `settings.json`, Codex — `hooks.json`, Kimi — `config.toml`.
Чужие хуки сохраняются; перед первой правкой существующего файла создаётся копия
`<файл>.pre-hgs`. Учитываются `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `KIMI_CODE_HOME`.
Вне запусков через hgs обработчики ничего не делают. **В Codex нужно доверить хуки
через `/hooks`**, если CLI предлагает проверку: hgs её не обходит. Отслеживаемый
Codex запускается с `--no-daemon`, чтобы его процесс принадлежал этой tmux-сессии.
Нужна версия Codex с этим флагом (проверена 0.160.0; 0.155.1 не подходит).
`HGS_TRACKING=0` отключает регистрацию для новых запусков.

`SessionStart` сообщает настоящий ID беседы; при смене беседы привязка обновляется.
События отправки запроса, вызова инструмента и завершения ответа обновляют занятость.
Сохраняются имя hgs, каталог, команда с аргументами, ID беседы и ключ текущего запуска.
Окружение с ключами и токенами не сохраняется. Если секрет передан непосредственно
аргументом команды, он, как и остальные аргументы, попадёт в запись — файлы доступны
только владельцу. Историю продолжает хранить сам агент.

Записи лежат в `${XDG_STATE_HOME:-~/.local/state}/hgs/sessions`, либо в `HGS_STATE_DIR`.
Запись атомарная, с синхронизацией на диск. Для каждой беседы хранится свой точный ID:
две сессии одного проекта не выбирают «последнюю историю каталога». Запоздавшие события
старого запуска и события субагентов не могут перепривязать сессию.

`pause` проверяет привязку живой панели, ID, существование истории, возможность собрать
точную команду восстановления и состояние простоя. Затем отправляет **SIGTERM только
отслеживаемому процессу**, сверив PID и время его создания, и ждёт выхода до 10 секунд.
Если агент не завершился, hgs сообщает об ошибке; SIGKILL и убийства всего tmux-сервера нет.
`pause --all` сначала проверяет **все живые сессии этого бокса**: занятый агент,
неотслеживаемая сессия или обычный shell остановят операцию до первого сигнала.
После начала остановки ошибки возможны для части сессий — команда вернёт ненулевой код
и перечислит их. Проверяй результат перед перезагрузкой.

Ограничения:

- Сессии, запущенные старым hgs, автоматически не подхватываются. `pause` их не убьёт.
  Для новой привязки нужно запустить через обновлённый hgs нужную беседу с явным ID.
- Пока агент не подтвердил ID и не создал историю, ставить на паузу нечего. Codex и Kimi
  могут создавать беседу лишь при первом сообщении. Проверенный Codex 0.160 также
  откладывает `SessionStart` после `resume` до следующего обращения: до подтверждения
  повторная пауза отклоняется. Первое сообщение после восстановления можно отправить
  из Activity: HGS проверяет точный процесс Codex, открытую им сохранённую историю с
  нужным ID и пустое родное поле ввода. Сам ID по-прежнему подтверждает только хук.
  Отключать tracking-хуки внутри сессии не следует.
- Пауза сохраняет беседу, а не процессы, открытые сетевые соединения или несданный
  черновик в поле ввода. Для занятого/неподтверждённого агента команда откажет: дождись
  завершённого ответа. После прерывания/ошибки агент может оставаться непроверенным
  до следующего нормально завершённого ответа.
- Поддержаны обычные интерактивные параметры запуска. Неизвестный флаг или режим
  вроде `codex exec` не угадывается: `pause` откажет до остановки. Исходный позиционный
  промпт не отправляется заново при восстановлении.
- История и конфиги агента должны остаться на той же машине. hgs не переносит беседы
  между машинами и не заменяет резервное копирование.

При восстановлении используется `claude --resume <id>`, `codex resume <id>` или
`kimi --session <id>`, включая исходный проектный враппер. Подстановки `--last` и
fallback в новую беседу здесь нет. `resume -d`/`resume --all` запускают процессы в фоне;
если нужен ввод пароля или доверие хукам, подключись через `hgs a …`.
Обычный запуск с сохранённым именем тоже восстанавливает его; `--fresh` явно заменяет
привязку новой беседой. `hgs kill <имя>` удаляет привязку hgs, сохраняя историю агента.

В JSON к живым отслеживаемым сессиям добавляются `resumable` и `activity`, а сохранённые
имеют `state: "paused"|"stopped"`, `attached: 0`, `clients: []`. Архивные записи имеют
`state: "archived"`, `archive_id` и `archived_at` и могут иметь то же имя, что живая сессия.
Отсутствие `state` означает обычную живую сессию — старые пиры совместимы.
Отдельные поля `runtime_state`, `process_state` и `conversation_state` различают
терминал tmux, процесс агента и жизненный цикл беседы. Хук `SessionEnd` не означает,
что процесс завершился: при живом процессе и неподтверждённой активности UI показывает
**Status unknown**. **Agent exited** означает, что процесс действительно завершился,
а его tmux-терминал ещё существует.
В **hgs zerus** пауза и восстановление доступны в карточке сессии.
В **Actions → машина** находятся **Pause all** и **Resume all in background**.
Пауза всех доступна, только когда все живые сессии готовы и их контекст отслеживается.
Сохранённые сессии также помечены в трее: клик открывает их карточку в hgs zerus,
где можно восстановить контекст. Массовое восстановление
запускает сессии в фоне, без открытия множества окон. Счётчик включает сохранённые сессии.

## Saved и Archive

**Saved sessions** — незаконченные беседы: явно поставленные на паузу или оставшиеся
после прерывания процесса, потери tmux или перезагрузки. **Archive** — завершённые
беседы. Ручной выход через `/exit` или `/quit` в новых отслеживаемых запусках переводит
беседу в архив. Она исчезает из Saved, обычного списка и трея; `resume --all` её не запускает.

С hgs 1.12 запуск отслеживается до реального завершения процесса. Для автоматического
архива нужны событие окончания основной беседы и успешный выход процесса без признаков
паузы или внешнего сигнала. Сам по себе `SessionEnd` недостаточен: Codex сообщает
`reason: other`, а Kimi использует `reason: exit` и для ручного выхода, и для SIGTERM.
Claude передаёт явный `prompt_input_exit`. Потеря соединения с терминалом не завершает
агента в tmux и не архивирует его. Причину выхода и код процесса можно увидеть через `inspect`.

Старые записи, в которых причина не сохранилась, автоматически не переклассифицируются.
Для них есть **Archive** в меню карточки Saved. Архивирование сохраняет историю агента
и точную привязку; **Forget archive** удаляет только запись hgs.

```bash
hgs archive codex/my-project/review                   # только остановленная сессия
hgs ls --local --json                                # архив: state=archived, archive_id
hgs inspect codex/my-project/review --archive <id>    # детали выбранной записи
hgs resume codex/my-project/review --archive <id> -d  # явное восстановление
hgs kill codex/my-project/review --archive <id>        # забыть только эту запись
```

Архив хранится в `archives/` внутри каталога состояния; у каждой записи собственный ID.
Повторный обычный запуск с тем же именем начинает новую беседу и не перезаписывает архив.
Если имя уже занято живой или Saved-сессией, Restore отказывает: существующая сессия
остаётся нетронутой. Архивная запись удаляется после подтверждения агентом того же
conversation ID; неудачный запуск не уничтожает привязку.

## Врапперы проекта

Если в каталоге проекта есть исполняемый `run_<cmd>.sh`, `hgs` запускает его внутри
tmux-сессии. Например, `run_claude.sh`, `run_kimi.sh` или `run_codex.sh` могут
подготовить окружение и запустить агента из каталога репозитория. Содержимое
враппера задаёт владелец проекта; приватные ключи в репозиторий не добавляются.

```bash
hgs codex sample-project             # ./run_codex.sh — новая беседа
hgs codex sample-project -c          # ./run_codex.sh resume --last
hgs codex sample-project -- resume <id>  # продолжить конкретную беседу
hgs codex sample-project --bare      # codex без враппера
```

Аргументы после `--` передаются врапперу как есть. Для Codex они отключают
автоматическую подстановку `resume --last`, даже с `-c`; продолжить беседу с опциями
можно через `-- resume --last --model <model>`. У Claude/Kimi `-c` передаётся врапперу
как `-c`. Без исполняемого враппера запускается обычная команда.

Для интерактивного `bw unlock` запускай без `-d`; detached-режим подходит, если ключ
уже доступен окружению tmux. Если сессия существует, `hgs` подключится к ней:
враппер и опции запуска применяются только при создании сессии.

## Установка

```bash
mkdir -p ~/.local/bin ~/.config/tmux ~/.local/src
git clone git@github.com:ufna/zerus.git ~/.local/src/zerus
bash ~/.local/src/zerus/install.sh
cp -f ~/.local/src/zerus/tmux.conf ~/.config/tmux/tmux.conf
```

`~/.local/bin` должен быть в `PATH`. Путь `~/.local/bin/hgs` обязателен — именно его
`hgs` зовёт на пире по ssh; поставишь CLI в другое место — локальный запуск будет
работать, а `hgs @peer …` и `hgs ls` по пирам молча сломаются. `cp` в
`~/.config/tmux/tmux.conf` перезапишет существующий глобальный конфиг tmux: `hgs`
использует дефолтный tmux-сервер (без `-L`), так что это общий конфиг машины, а не
приватный сокет инструмента.

Конфиг — `~/.config/hgs/config` (`HGS_SELF`, `HGS_PEERS`, `HGS_TAB`, `HGS_TAB_COLORS`)
и локальные псевдонимы папок `~/.config/hgs/projects.local`. Пример рабочего конфига:

```bash
HGS_SELF="arch workstation"            # имена, означающие «это я», для @host
HGS_PEERS="mac"                   # ssh-алиасы, которые опрашивает ls и куда ходит @host
HGS_TAB=1                         # 0 — не трогать вкладку терминала
HGS_TAB_COLORS="mac=#80ff80"      # цвет вкладки по боксу; ключ local красит и свои сессии
```

На Mac ставится с другой машины: `./mac-install.sh <ssh-алиас> [--no-tray]`.
Скрипт доставляет исходники Rust, Cargo.lock и конфиг сборки в `~/.local/src/hgs`,
собирает CLI на самом Mac и атомарно заменяет `~/.local/bin/hgs`. Если Cargo отсутствует,
устанавливает Rust через Homebrew. С `--no-tray` обновляется только CLI; по умолчанию
также доставляются и собираются исходники Qt-приложения. Каталоги сборки Linux на Mac
не копируются. Обновление исполняемых файлов не перезапускает tmux или агентов.

Файл `hgs` в репозитории — короткий launcher для разработки; сначала выполни `cargo build`.
Установщик ставит непосредственно скомпилированный бинарь. Файл `config` поддерживает
присваивания перечисленных выше переменных, кавычки и переменные окружения;
произвольные shell-команды в нём не выполняются.

Настройки подключения машин по-прежнему могут управляться инфраструктурой.
Проекты теперь создаются и редактируются в Zerus.

### Общий каталог проектов

В **Projects → Swarm…** можно подключить эту машину к рою через любую уже
подключённую машину. Сначала настройте SSH-доступ в **Computers** и откройте
Zerus на обеих машинах: существующие проекты один раз импортируются в HGS.
На вкладке **Connect computer** выберите подключение, нажмите **Preview connection**, проверьте сопоставление
проектов и нажмите **Join and merge projects**. Одинаковые названия сами по себе
не объединяют проекты. По умолчанию для сессий, которые уже есть в рое,
сохраняется его распределение по проектам; опцию можно снять, чтобы сравнить
конфликтующие назначения. Перед объединением HGS сохраняет резервную копию.

Вкладка **Computers** показывает прокручиваемый список машин с поиском по имени,
локальному подключению и состоянию. Обновления сохраняют выделение и прокрутку.
Предпросмотр подключения и **Conflicts** занимают отдельные вкладки, поэтому
появление сопоставления проектов не сдвигает другие блоки окна.

Третий компьютер подключается тем же способом через любого доступного участника.
Постоянного главного узла нет: каждый хранит весь каталог и может передавать изменения
дальше. Для обмена в обе стороны достаточно одного настроенного SSH-подключения.
На другой стороне не требуется обратный SSH-доступ. Дополнительное подключение
к уже известному участнику добавляется через тот же просмотр и **Connect this member**.

Общие данные: ID и названия машин, ID/названия/цвета проектов, расположения папок
и принадлежность сессий проектам. Локальные данные: SSH-адреса, пользователи, порты,
ключи, прокси, учётные данные, соответствие ID машины её локальному подключению,
порядок, свёрнутость, насыщенность оформления, фильтры и проект по умолчанию. Файлы и история агентов не
копируются. Получение ID машины через каталог не создаёт подключение к ней.

В рабочих списках доступны проекты с папками или сессиями на машинах, доступ
к которым настроен здесь, а также пустые проекты, куда можно добавить папку.
Временно выключенная машина не скрывает проект. **All swarm projects** показывает
и проекты без локального подключения; его можно настроить через **Swarm → Manage connections…**.

HGS хранит каталог и локальные привязки в `~/.config/hgs/swarm/catalog.json`.
Этот файл целиком переносить между машинами не следует: в нём есть собственная
идентичность узла и его локальные привязки. `hgs swarm export` возвращает только
общий каталог. Старые настройки Zerus сохраняются в `workspace/organizationBeforeSwarm`,
а копии перед импортом и объединением — в `~/.config/hgs/swarm/backup-*.json`.

Служба `hgs-swarm` (`com.hgdev.hgs-swarm` на Mac) работает независимо от окна Zerus.
Без подключённых участников сетевых запросов нет. При изменении местного каталога
обмен начинается после ближайшей проверки (обычно до 3 секунд); без изменений
участники проверяются раз в 30 секунд. При ошибках интервал увеличивается до 5 минут.
Zerus читает локальный каталог раз в 5 секунд; эта проверка не обращается к SSH.
После восстановления сети сохранённые изменения догружаются. Независимые поля
сливаются, конфликтующие значения остаются в **Swarm → Conflicting changes**,
где можно выбрать нужное. Удаления сохраняются в журнале и не отменяются старой
копией, которая вернулась в сеть. В этой версии старые записи журнала не удаляются.

Команды для диагностики:

```bash
hgs swarm get
hgs swarm preview mac
hgs swarm sync
hgs swarm disconnect mac
```

`disconnect` прекращает исходящий обмен через это подключение, сохраняя каталог
и доступ к сессиям. Он не запрещает другой уже подключённой машине обмениваться
с этой: транспортный доступ регулируется локальной конфигурацией SSH.
Установку службы можно отключить через `HGS_SWARM_SERVICE=0 bash install.sh`.

### Локальные псевдонимы папок для CLI

Zerus управляет логическими проектами в общем каталоге HGS. Старый
`~/.config/hgs/projects`, создававшийся Ansible, больше не читается.
Для совместимости CLI оставлен `~/.config/hgs/projects.local` (`имя=каталог`):

```
hgs project ls --json
hgs project add infra ~/work/infra
hgs project set infra ~/work/other
hgs project rm infra
```

Эти псевдонимы один раз импортируются в проекты Zerus для каждой подключённой
машины. Последующие изменения проектов выполняются в приложении. CLI также
запускает сессии по абсолютному пути. Имя псевдонима не содержит пробелы, `/`, `=`;
на название логического проекта это ограничение не распространяется.

Исходники Zerus распространяются по [MIT](LICENSE); лицензии сторонних компонентов
описаны в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Разработка ведётся в
`ufna/zerus`. Команда `hgs`, пути настроек и системные идентификаторы приложения
сохранены для совместимости с существующими установками.

Настройки машин, SSH-ключи, аккаунты и журналы сессий остаются локально.
В примерах используются вымышленные папки и имена. `mac-install.sh` требует
явный SSH-алиас назначения и использует существующую SSH-конфигурацию.
По умолчанию он не настраивает обратное подключение. Для явной настройки нового
пира задайте `HGS_MAC_PEER` и `HGS_MAC_PEER_HOST`; при необходимости —
`HGS_MAC_PEER_USER`, `HGS_MAC_PEER_KEY` и `HGS_MAC_PEER_COLOR`.
Если SSH-алиас пира уже настроен на Mac, достаточно `HGS_MAC_PEER`.


## JSON (`hgs ls --json --local`)

Машиночитаемый снимок **одного бокса**, без ssh. Печатается вручную (без `jq`, который не
гарантирован ни в PATH тестов, ни на маке); при пустом tmux-сервере не падает, просто
`"sessions":[]`. `--dry-run` показывает реальные `tmux list-clients`/`list-sessions -F …`,
которые он запускает.

```jsonc
{
  "host": "arch",                    // string — HGS_SELF, первое имя
  "ok": true,                        // bool
  "projects": { "sample-project": "/workspace/sample-project" },  // object: string -> string (path)
  "sessions": [
    {
      "name": "claude/sample-project/review",  // string — полное имя tmux-сессии
      "cmd": "claude",                      // string, может быть пустой
      "project": "sample-project",             // string | null
      "tag": "review",                      // string | null
      "attached": 1,                        // int — число подключённых клиентов
      "clients": ["/dev/pts/2"],            // array of string — их tty
      "created": 1787840176                 // int — unix-эпоха создания сессии
    }
  ]
}
```

`hgs ls --json` без `--local` — то же самое, но по всему флоту: JSON-массив, этот бокс
первым элементом (тот самый объект выше), затем по одному объекту на каждого пира из
`HGS_PEERS` (опрашивает их по ssh, как обычный `hgs ls`). `hgs @peer ls --json` — тот же
опрос одного конкретного пира, без обёртки в массив. Пир, до которого не достучались, или
который ответил не JSON-объектом (старый `hgs` без `--json`) — это состояние, а не ошибка:
объект приходит с `"ok":false` и `"error":"offline"|"bad_response"`, `hgs` при этом
завершается кодом 0.

`hgs notify [--bell] <session> [text]` — пишет одну строку JSON-события (`session`,
`host`, `text`, `bell`, `ts`) в файл событий трея (`$HGS_EVENTS`, иначе
`~/Library/Application Support/hgs/events` на маке или
`$XDG_RUNTIME_DIR/hgs/events`/`/tmp/hgs-<uid>/hgs/events` на линуксе). Файла нет — трея
нет — это no-op, а не ошибка; спула на будущее намеренно нет.

## Вкладка терминала

Пока ты подключён, заголовок вкладки = имя сессии (`mac:codex/repo` для чужого бокса),
в Konsole вкладка ещё и красится по боксу; на выходе всё откатывается. Заголовок —
`OSC 30` + `OSC 0`, цвет — D-Bus `org.kde.konsole.Session.setTabColor` (escape-
последовательностей для цвета Konsole не понимает). `HGS_TAB=0` выключает.

## Обрыв ssh

tmux на пире переключает твой терминал в alt-screen, включает отчёты мыши, bracketed paste,
focus-события, application cursor keys — и откатывает всё при detach. Если ssh-линк умирает
(VPN упал, пир уснул; ssh пишет `Timeout, server … not responding` и выходит с 255), откат не
доезжает: ssh восстанавливает только termios, и шелл получает каждое движение мыши строкой
вида `35;26;1M`, а экран остаётся в alt-screen без скроллбэка. `hgs` отличает такой обрыв от
«не подключился» по маркеру, который ssh трогает через `LocalCommand` сразу после соединения,
и проигрывает откат tmux сам: `hgs: link to mac dropped; the session is still there, rerun to
reattach`. Сессия на пире живёт, повторный `hgs @mac …` подцепится к ней. Код 255 без
соединения терминал не трогает — там он и не менялся.

## Смерть локального tmux-сервера

Та же рана ближе к дому. Терминалом владеет **сервер** (клиент только отдаёт ему fd), поэтому
и переключение, и откат пишет он. Когда сервер не отсоединяется, а умирает — сегфолт в
`tty_keys_next`, OOM, `kill -9`, — клиент умеет только выйти с кодом 1, и шелл возвращается
с включёнными отчётами мыши (клик печатает в промпт `[<0;53;12M`), в alt-screen и с
bracketed paste. `hgs` проигрывает тот же откат, что и при обрыве ssh; доказательством, что
терминал был именно tmux'овый, служит пропавший сервер:

```
hgs: the tmux server died; terminal restored, sessions on this box are gone
```

Живые процессы этого бокса потеряны — переживает их только сам сервер, не tmux-сокет.
У отслеживаемых сессий остаются привязки: `hgs resume --all` восстановит сохранённые
беседы по ID. Для старых неотслеживаемых сессий `hgs claude <проект> -c` подхватит последнюю.
Клиент, вышедший ненулём при **живом** сервере (нет такой сессии, кривые аргументы),
терминала не касался — ему ничего не шлём: `\033[?1049l` на обычном экране увёл бы курсор
в устаревшую сохранённую позицию.

## Картинка по Ctrl+V из удалённой сессии

Ctrl+V для Claude Code — не вставка терминала: агент сам читает буфер **своей** машины
(`wl-paste` на арче, `osascript` на маке). В сессии, к которой ты подключился с другого
бокса, он честно смотрел в чужой буфер, а скриншот лежал в твоём. Теперь `tmux.conf`
перехватывает C-v и зовёт `hgs paste`: тот по `HGS_CLIENT` из env сессии (его ставит `hgs`
при каждом attach и при создании — `local` или имя пира, хоп `hgs @mac …` передаёт его сам
через `--client`) забирает PNG с бокса, за которым ты сидишь (`ssh <пир> hgs clip`), кладёт
в буфер бокса сессии и пробрасывает C-v дальше. Агент находит картинку там, где всегда
искал: `[Image #1]`. Локальная сессия — как раньше, без сети.

Что видно в статусной строке tmux: `hgs: pulling clipboard from mac`, потом либо ничего
(вставилось), либо `no image in mac clipboard` / `mac unreachable, pasting local clipboard`.
Ctrl+V пробрасывается в любом случае.

Из-за этого «в любом случае» провал внешне неотличим от успеха, а сообщения в статусной
строке висят считаные секунды, поэтому каждый C-v пишет одну строку в
`${XDG_STATE_HOME:-~/.local/state}/hgs/paste.log` (на боксе сессии): ветку, rc, длительность
ssh и размер PNG — `who=mac rc=0 ssh=1s bytes=183422 set=ok`, `rc=1 … no-image-on-mac`,
`rc=255 … ssh-failed`, `who=local local-passthrough`. Пишется best-effort: недоступный лог
вставку не ломает; не ротируется (строка на нажатие).

Цена и ограничения: один ssh-раундтрип на каждый Ctrl+V в удалённой сессии (~0.3–1 с по
Nebula), только PNG (Spectacle и скриншоты macOS его отдают), буфер бокса сессии
перезаписывается картинкой. После обновления `tmux.conf` живой сервер подхватывает бинд
по `tmux source-file ~/.config/tmux/tmux.conf` (`mac-install.sh` делает это сам).

## Графический env сессии, созданной с пира

Сессия наследует окружение того, кто её создал, а с пира это ssh-логин: `XDG_SESSION_TYPE=tty`
и ни `WAYLAND_DISPLAY`, ни `DISPLAY`, ни `XAUTHORITY` (tmux ещё и помечает их в env сессии как
удалённые, так что и перезапущенный пейн остаётся слепым). Мост C-v при этом отрабатывал
честно — `wl-copy` кладёт PNG в буфер компози́тора, — но агент внутри его не видел: **codex**
(крейт `arboard`) идёт в Wayland, только если `WAYLAND_DISPLAY` **выставлена**, иначе
откатывается на X11 и падает с `X11 server connection timed out because it was unreachable`.
Сессия, созданная локально из терминала бокса, той же проблемы не имела.

Поэтому на Linux `hgs` при **создании** сессии добирает недостающие переменные и передаёт их
в `tmux new-session -e`: значения берутся из менеджера пользователя systemd
(`systemctl --user show-environment` — их туда кладут pam_systemd и композитор), а для
`WAYLAND_DISPLAY` есть запасной путь — тот же скан сокета `XDG_RUNTIME_DIR/wayland-*`, что и в
`hgs clip`. Уже выставленные переменные не трогаются (локальная сессия и так их наследует),
`XAUTHORITY` с несуществующим файлом (логин уже закрыт) не передаётся: протухшее значение
хуже отсутствующего. На macOS ничего не добирается — буфер и GUI там env не требуют.

Видно это в `hgs --dry-run`:
`tmux -u new-session -e HGS_CLIENT=mac -e WAYLAND_DISPLAY=wayland-0 -e DISPLAY=:1 -e XAUTHORITY=… -s codex/proj …`

Ограничение: значения фиксируются в момент создания сессии. Пережившая перелогин в графику
сессия будет держать старые (`XAUTHORITY` точно сменится) — лечится пересозданием сессии.

## Трей (`tray/`, Linux + macOS, Qt6)

Бейдж значка в панели задач Linux (Plasma / Unity LauncherEntry) и Dock macOS
показывает число сессий **Needs attention**. При нуле бейдж скрывается; после
перезапуска оболочки Linux публикуется заново. Счётчики системного трея сохраняются.

Иконка приложения Zerus — **Swarm**: три лезвия. На macOS для Dock, ⌘Tab и Finder
используется отдельная композиция Icon Composer: светлые лезвия с мягким объёмом
на графитовой градиентной подложке. Скругления, освещение и варианты оформления
задаёт система. Заголовок окна и Linux-лаунчер используют монохромный
`hgs-zerus-symbolic.svg` без подложки, чтобы композитор
не мог выбрать и уменьшить объёмную картинку. Геометрия совпадает со знаком трея.
Установщик прописывает в Linux-лаунчере абсолютный путь к SVG: это исключает
подстановку стандартной иконки исполняемого файла при поиске локальной иконки
по имени темы в Plasma. После изменения лаунчера обновляется кэш KDE.
Монохромные PNG в `tray/resources/icons/` генерируются из `IconFactory::brandPixmap`:
`cmake --build tray/build --target hgs-export-icons`, затем
`QT_QPA_PLATFORM=offscreen tray/build/hgs-export-icons tray/resources/icons`.
Исходник macOS — `tray/resources/icons/hgs-zerus-swarm.icon`, его можно открыть в
Icon Composer. SVG сохраняет геометрию Swarm с отдельным отступом для подложки.
После изменений выполните на Mac с Xcode 26+ `bash tray/tools/export-macos-icon.sh`:
он обновит `macos/Assets.car` и совместимый `hgs-zerus-swarm.icns`. Оба ресурса хранятся
в репозитории; обычная сборка не требует Icon Composer. AppKit использует иконку
бандла целиком, чтобы Dock сохранял системное оформление и доступные разрешения.
Подложка соответствует [рекомендациям Apple](https://developer.apple.com/design/human-interface-guidelines/app-icons):
квадратные слои 1024×1024 без заранее нарисованных скруглений.
Монохромный знак и сравнение с предыдущей Z сохранены в
`design/zerus-icons/monochrome-v6.html`; материалы прежней иконки — в
`design/zerus-icons/z-materials-v5.html`.

`hgs-tray` — иконка в системном трее: лезвия Swarm и два счётчика сессий
(свой бокс + известные пиры). Для маленьких размеров используется чистый векторный
силуэт без текстуры. Верхний счётчик показывает общее число сессий, нижний — число
ожидающих ответа, разрешения или исправления ошибки сессий на доступных машинах.
Оба числа видны одновременно, в том числе нули; каждое ограничено `99+`.
Ненулевой Needs attention выделяется янтарным фоном. Контрастные подложки сохраняют
читаемость на светлой и тёмной панели Linux и macOS; `--icon-color` задаёт цвет
верхнего счётчика и знака Swarm. При ошибке связи показываются `?`.
Если пир недоступен или не отвечал дольше 3 минут, появляется точка сверху справа.
Точные числа доступны также в подсказке. Общее число сохраняет последний известный снимок
спящей машины. В меню — секция на бокс, в ней имя
каждой сессии (`●` перед именем — кто-то уже приаттачен). Первый пункт **Open hgs**
открывает hgs zerus; ниже сессий остаются **Open in**, **Refresh** и **Quit**.
Создание, пауза, восстановление, завершение сессий и управление проектами находятся в менеджере.
Клик по живой сессии — то же, что `hgs a <имя>` (для пира — `hgs @<alias> a <имя>`):
attach в терминале выбранного бэкенда (Konsole на Linux, `Terminal.app` на Mac,
если не задан `--terminal`/`terminal=`).

**ЛКМ** открывает список сессий в hgs zerus, поднимая и восстанавливая уже созданное окно.
**ПКМ** открывает короткое меню. На Linux `KStatusNotifierItem` передаёт активацию приложению,
а меню по DBusMenu рисует панель Plasma. На Mac `QSystemTrayIcon` передаёт клики приложению;
по ПКМ показывается нативное NSMenu с делегатом Qt. Обновления иконки по-прежнему откладываются
на время открытого меню.

### Machines: подключение и установка

**Machines** — отдельный экран: имя SSH-подключения, hostname/IP, пользователь, порт,
путь к ключу, включение в список машин. Пустые поля наследуют `~/.ssh/config`.
Изменения сохраняются в `~/.config/hgs/machines.local.json`; общий `config` остаётся
нетронутым. **Test connection** проверяет SSH и версии hgs/tmux. **Open SSH terminal**
позволяет пройти обычное SSH-подключение и подтвердить ключ нового хоста.
**Add machine** создаёт в списке временную строку **New machine**. До **Save connection**
она не меняет конфигурацию. При переходе на другую машину **Cancel** или Escape
оставляют черновик выбранным и сохраняют введённое; **Discard draft** удаляет его.
**Install hgs** собирает и устанавливает CLI на удалённом Linux/macOS с журналом
прогресса. Нужны Rust 1.85+ и tmux на целевой машине. Исходники берутся из локального
`~/.local/src/hgs` или выбранного checkout; существующие проекты и сессии сохраняются.

Эффективные параметры подключения показаны отдельно: SSH alias, hostname, user, port,
пути к ключам и jump host. Они получаются через `ssh -G` без подключения к машине;
`hgs machine resolve mac` возвращает ту же информацию. Поля формы — только overrides:
пустое значение оставляет действующим унаследованный SSH-конфиг.

Фильтр над списком сессий поддерживает несколько машин одновременно. Выбранные машины
показаны цветными метками, каждая снимается отдельно. **All machines** очищает ограничение;
фильтр применяется и к поиску по содержимому. **Label color…** в Machines настраивает
цвет, включая локальную машину; **Automatic** возвращает цвет по умолчанию.
Режим **Bright** использует выбранный цвет без приглушения и подбирает контрастный
чёрный или белый текст; **Soft** оставляет спокойную подложку. Результат виден в Preview.
Цвета и режим — предпочтение интерфейса, сохраняются на этом устройстве.

Метки провайдера и машины одинаковы в списках сессий, аккаунтов и результатов
поиска, в шапке сессии и на дашборде. Машина использует свой настроенный цвет.
Контур клавиатурного фокуса появляется после Tab/стрелок и скрывается после клика;
обычное выделение выбранной строки сохраняется.
Карточки сессий и сабагентов не показывают дублирующую сводку при наведении:
подробности доступны в Activity и Details. Описания для экранного диктора сохранены.
Обновления Activity применяют журнал и подтверждения отправки одновременно:
локальная карточка переходит в запись журнала без дубликата и повторной загрузки
миниатюры. Выделенный текст и место чтения сохраняются; индикатор контекста остаётся
у правого края над полем ввода.
Файлы можно перетащить на всю открытую панель сессии: шапку, Activity, Details или
Terminal. Подсветка показывает область приёма; файлы добавляются в черновик сообщения
без отправки. В открытой Activity сабагента вложения попадают в его черновик.
Записанные Claude блоки `thinking`, включая промежуточные сообщения из терминала,
видны отдельными сворачиваемыми карточками **Thinking**. Начало текста видно сразу;
полный текст раскрывается по клику. Эти записи не считаются завершённым ответом.
Основные сессии имеют одинаковый отступ. Список сабагентов раскрывается кнопкой
со счётчиком справа внизу карточки; вложенный отступ есть только у дочерних строк.
Провайдер стоит в строке имени, машина — напротив проекта и ветки. Текущая операция
занимает отдельную строку; модель, effort и счётчик сабагентов выровнены по центру нижней строки.
Шапки Overview, Machines и Agent accounts используют одинаковые кнопки и отступы:
обновление слева, создание/добавление — крайней справа. Шапка Overview остаётся на месте при прокрутке.

**Pinned** закреплена перед остальными группами. **Pin session** в меню сессии
помещает её туда, **Unpin session** возвращает в предыдущую группу (или Ungrouped,
если прежняя группа удалена). Перетаскивание также работает. Порядок закреплённых
сессий и состояние сворачивания сохраняются; счётчики внимания и работы видны на
заголовке свёрнутой группы. Пустая Pinned появляется рядом с пользовательскими
группами; в плоском списке достаточно закрепить первую сессию через меню.

В **New session → Project** можно заранее выбрать проект.
Группа применяется к конкретному успешному запуску, даже после задержки на ввод пароля
или перезапуска Zerus. Неудачный запуск не перемещает уже существующую одноимённую сессию.

Работающие сессии имеют зелёную плашку **Working (17m 56s)** с плавно пульсирующим индикатором;
если агент передаёт время начала запроса, таймер показывает длительность текущей работы.
Вызовы инструментов и сообщения в очереди его не сбрасывают. Время обновляется локально,
раз в секунду, в том числе при отключённой анимации, без дополнительных запросов к машинам;
паузу обозначает фиолетовая плашка **Paused**. Фон строки зарезервирован для выбора
и наведения. Модель и отдельная плашка effort стоят рядом; декоративных разделителей-точек
в подписях приложения нет. Пульсация отключается в Settings → Animate working sessions
и не создаёт дополнительных запросов к машинам.

Завершённый непросмотренный ответ выделяется янтарной плашкой **New reply** и входит
в **Needs attention**, счётчики групп и дашборд. Ready без нового ответа не требует
внимания. Отметка опирается на завершённый ответ основного агента в журнале, поэтому
не пропускает быстрый ответ между опросами и не срабатывает от завершения подагента.
Просмотр учитывается только в активном окне Zerus: ответ виден в последней части
Activity или открыт подключённый Terminal внизу вывода. Фоновое/свёрнутое окно и
поиск по старым сообщениям отметку не снимают. Просмотр сохраняется на этом устройстве
по машине и разговору; переименование и resume не делают старый ответ новым.
Жёлтые запросы разрешения/ввода остаются отдельным состоянием и не снимаются просмотром.
ПКМ открывает меню нажатой сессии без переключения разговора. **Mark as read**
снимает текущее уведомление и ручную пометку, но не отвечает на запрос агента;
новое событие снова может потребовать внимания. **Mark needs attention** сохраняет
напоминание «посмотреть позже» на этом устройстве, включая офлайн-сессии.
Открытие разговора напоминание не снимает; кнопка **Mark as read** с иконкой
над полем ввода слева явно снимает отметку. Позиция чтения и черновик сохраняются.

**Mark all as read** в меню по ПКМ на пустом месте списка и в меню **…** над сессиями
снимает отметки новых ответов сразу на всех машинах, включая скрытые фильтром,
свёрнутыми группами и временно недоступные сессии с сохранённым снимком.
Счётчик команды показывает число непросмотренных разговоров; когда их нет, команда
недоступна. Отметки сохраняются на этом устройстве после перезапуска. Новые ответы
снова выделяются; запросы разрешения, вопросы и ошибки остаются требующими действия.
Открытая беседа и её черновик сохраняются при очистке отметок в фильтре внимания.

### Папки и worktree

В отдельной вкладке **Worktrees** рядом с **Details** и в **Projects → выбранная папка** доступен каталог рабочих копий
репозитория на выбранной машине. Обычные папки без Git показываются вместе со
связанными сессиями. Для Git видны основной checkout, linked worktree, ветка или
короткий SHA detached HEAD, locked/prunable и недоступные копии. Связанные сессии
сопоставляются по подтверждённой папке или корню checkout на той же машине.

Клик по рабочей копии фильтрует Sessions, сохраняя открытую беседу и черновик;
выбор дочерней сессии открывает её. Фильтр сочетается с поиском и машиной,
снимается кнопкой над списком; **All sessions** снимает все фильтры.
Кнопка **New session…** открывает форму с выбранной папкой и прежним проектом.
В **New session → Other worktrees…** можно выбрать существующую копию, сохранив
проект, машину и аккаунт. Папка добавляется в проект только после успешного запуска.
Недоступные и bare-копии не предлагаются для запуска; обычный Browse остаётся доступным
без Git, даже при ошибке чтения Git-метаданных. Перед запуском папка проверяется снова.

**New session → New worktree…** создаёт рабочую копию на выбранной машине.
Укажите новую ветку, исходную ветку/тег/коммит (по умолчанию `HEAD`) и новый путь;
папка по умолчанию предлагается рядом с исходной копией. **Parent folder…** выбирает
другой родительский каталог, в том числе на удалённой машине. Родительская папка должна
существовать; занятые ветки и пути отклоняются без перезаписи. После **Create worktree**
подтверждённая папка выбирается в форме с прежними проектом, машиной и аккаунтом.
Она добавится в проект после **Start session**. Если отменить форму или запуск агента
не удастся, созданные папка и ветка сохраняются. Для папок без Git этот шаг не требуется.

CLI: `hgs [@host] worktrees create --path /repo --branch feature/task --destination /repo-task --base HEAD --json`.
Zerus дополнительно передаёт `--common-dir` для проверки выбранного репозитория
и `--request-id` для подтверждения ответа. Создание использует обычный `git worktree add -b`,
включая настроенные checkout hooks, без `--force`, fetch и удаления существующих файлов.
Исходный ref разрешается в commit до создания. Операция ограничена пятью минутами;
при ошибке или потере соединения нужно проверить указанную папку перед повтором.
Автоматического удаления частичного результата нет.

Каталог читается по требованию, при открытии раздела или через **Refresh**, а не
на каждом тике опроса. `hgs [@host] worktrees --path /absolute/folder --json`
возвращает canonical `path`, `common_dir`, `selected_root`, `state`, `sampled_at`,
`partial`, `stale` и `worktrees`; `--refresh` обходит 30-секундный кэш репозитория.
Идентичность репозитория — машина и canonical Git common directory; независимые
клоны и одинаковые пути на разных машинах не объединяются. Git вызывается с
аргументами без shell-интерполяции, общим бюджетом 3 секунды, максимумом 1 MiB
вывода и 512 копий. Состояния `not_repo`, `git_unavailable`, `metadata_error`,
`timeout`, `too_large`, `folder_unavailable` различаются. При ошибке доступный
предыдущий снимок помечается устаревшим; offline показывает сохранённые данные
и отключает запуск. Zerus хранит до 64 снимков общим размером до 8 MiB.

[Дизайн папок и worktree](design/worktree-support/index.html) описывает также будущую
ручную очистку копий. Закрытие или архивирование сессии не удаляет файлы и ветки.

### Главная страница

Клик по логотипу открывает **Overview**: требующие внимания и работающие сессии,
число доступных машин, CPU, память и load average каждой машины. Сводные счётчики
открывают соответствующий фильтр, карточка сессии — её Activity, шестерёнка — Machines.
Карточки сессий расположены адаптивной сеткой; одиночная карточка занимает одну
ячейку, а на узком окне сетка переходит в одну колонку. Полоски CPU и памяти
становятся оранжевыми от 70%, красными от 90%; старые и недоступные замеры серые.
Метрики приходят вместе с обычным опросом HGS. CPU считается по разнице двух замеров;
первый замер не подменяется нулём. На Linux память учитывает MemAvailable,
на macOS — app + wired + compressed. Недоступные машины сохраняют последний замер
с его временем и отметкой Offline/Stale; старые данные не считаются текущими.

### Аккаунты AI-агентов

В **Agent accounts** можно переименовать обычный или родной профиль через **Rename**.
Меняется только название в HGS; ID, вход и привязки существующих сессий сохраняются.
Справа показаны доступные имя, логин, организация, тариф и использование лимитов.
Полоски означают **использованную** долю общей квоты аккаунта, с периодом и временем
сброса. Пороги цвета: 70% — оранжевый, 90% — красный. В нижней строке открытой сессии
есть компактный индикатор; нажатие открывает её профиль на соответствующей машине.

Снимок лимитов общий для всех сессий одного профиля на одной машине и сохраняется
при переключениях. Автообновление — раз в пять минут, пока открыт соответствующий
экран; маленькая кнопка рядом с индикатором запрашивает свежий снимок вручную.
При наведении кнопка подсвечивается, а во время запроса её стрелка вращается.
Во время обновления или ошибки остаются последние значения с отметкой состояния.
Индикатор прижат вправо: проценты стоят компактно, дополнительный текст времени
до сброса расширяет только свой показатель. В **Overview → Accounts**
видны карточки в две строки: название с бейджами, затем логин/тариф рядом с
компактными квотами. Время обновления доступно
в подсказке. Тонкая полоска слева показывает цвет расхода максимальной квоты;
без данных о квоте полоска серая. Карточка открывает нужный аккаунт. Число сессий вынесено в отдельный
блок верхнего ряда рядом с Working, Needs attention и Machines online.
**Refresh** также обновляет сводку аккаунтов. Codex использует родные `account/read` и
`account/rateLimits/read` ([App Server](https://learn.chatgpt.com/docs/app-server)).
Claude использует `auth status --json` и свой OAuth usage endpoint; если сохранённый
доступ истёк, требуется обновить вход через родной агент. Kimi читает родные квоты
5h/7d и месячные окна, когда они доступны; обновление OAuth выполняет сам Kimi через
его [локальный API](https://moonshotai.github.io/kimi-code/en/reference/server-api.html).
Официальный DSH предоставляет сведения и кошельки родного DeepSeek account через
свой авторизованный UI API. Вход по отдельному API-ключу не подменяется аккаунтом
подписки. Отсутствующие данные, истёкшие окна и просроченный вход явно отмечаются;
нулевой расход не выводится вместо ошибки. Кэш содержит только сведения для показа,
без токенов и ключей; запросы не запускают inference и не отправляют сообщений.

**Agent accounts** показывает один аккаунт со всеми его машинами, в том числе на
дашборде. Профили объединяются по сообщённому провайдером ID аккаунта либо email
с учётом организации. Разные провайдеры, организации и конфликтующие ID остаются
отдельными; одинаковое название **Default account** не считается совпадением.
При первом открытии **Loading accounts…** показывается до первых готовых результатов.
Локальные аккаунты появляются, не дожидаясь остальных машин; удалённые догружаются
со статусом **Updating…** и сразу объединяются по подтверждённой идентичности.
Новые профили с ещё неизвестной идентичностью не показываются до окончания проверки,
чтобы список не раздувался временными дубликатами. При фоновом обновлении сохраняются
известные строки и выбор; ошибка или недоступная машина не оставляют страницу
в бесконечной загрузке.
Рядом со статусом загрузки и обновления вращается небольшой жёлтый индикатор;
после завершения он исчезает, сохраняя положение текста. На скрытой странице
анимация приостанавливается.
Профили без установленной идентичности пока показываются отдельно.
Под аккаунтом видны теги машин. Выбор тега переключает вход и удаление на эту
машину; **+ имя машины** предлагает скопировать авторизацию или войти заново.
Лимиты общие: показывается один актуальный снимок, расход разных машин не суммируется.
Переименование аккаунта последовательно обновляет его профили на машинах.
Кнопка в Machines фильтрует аккаунты по выбранной машине. Нативные **Default**
используют существующую авторизацию; **Add account** создаёт отдельный профиль
на выбранной машине и открывает обычный вход провайдера в терминале.
В **New session** аккаунт выбирается для текущего агента и машины.
**Make default on …** назначает аккаунт по умолчанию для новых сессий этого агента
на выбранной машине. То же через CLI: `hgs @mac account default PROFILE_ID`.
После этого `hgs claude` на Mac (или `hgs @mac claude` с другой машины) использует
выбранный профиль без `--account`. Явный `--account` имеет приоритет; открытие,
возобновление и форк существующей сессии сохраняют её аккаунт. В **New session**
профиль отмечен **(default)** и выбран заранее. Обычная команда `claude` без HGS
сохраняет свой нативный вход. Для возврата к нему в HGS:
`hgs @mac account default native-claude`. Удаление профиля из каталога также
снимает его назначение по умолчанию.
HGS не разблокирует macOS Keychain перед запуском Claude: доступ к credentials
выбранного профиля обрабатывает сам Claude. На Mac установщик добавляет пользовательский
LaunchAgent `com.hgdev.hgs.user-session`, который по запросу подключает процесс HGS
к уже открытой графической сессии того же пользователя. Это нужно перед входом,
проверкой аккаунта и запуском Claude из tmux: отдельные SSH-подключения имеют свои
контексты безопасности и не наследуют разблокировку Keychain. Сервис передаёт
системное право присоединиться к сессии, проверяя UID обеих сторон; пароли и токены
через него не проходят. Он запускается по требованию и завершается после минуты простоя.
Нужен вход пользователя в macOS; блокировка экрана и выход из учётной записи — разные
состояния. Если Keychain действительно закрыт и в графической сессии, его нужно
разблокировать там. Zerus отличает эти случаи от отсутствия входа в Claude.
Обычный OAuth, обновление токенов, лимиты и коннекторы остаются нативными.
Пауза, восстановление и форк сохраняют профиль исходной сессии.

Каталог `~/.config/hgs/accounts.json` содержит метаданные профилей и выбранные режимы разрешений;
авторизация хранится в собственном каталоге профиля. HGS не показывает токены в UI
и не проверяет действительность входа по одному наличию файла. Managed-профили
очищают унаследованные API-токены перед запуском агента; Default сохраняет обычное
окружение пользователя. Для отдельных профилей Claude поддержан claude.ai login;
общая авторизация Claude Console не изолируется этим механизмом. После успешного
входа и проверки native auth status HGS завершает первоначальную настройку
отдельного профиля Claude, чтобы первый запуск не повторял мастер авторизации.
Разрешения и доверие к рабочим папкам при этом не меняются.
Стартовый вопрос Claude **Accessing workspace / Trust this folder?** отображается
в Activity с полным видимым предупреждением и двумя явными вариантами ответа.
Распознаются и уже запущенные сессии, в которых над вопросом остались строки
старой проверки Keychain HGS; произвольный текст перед диалогом не принимается
за подтверждаемый запрос.
Перед запуском управляемого профиля Claude HGS наследует поведенческие настройки
из `~/.claude/settings.json`, включая `permissions.defaultMode`, модель и effort.
Изменения пользовательского файла подхватываются при следующем запуске или resume;
собственные переопределения профиля сохраняются. Авторизация, API-ключи, endpoints,
config-directory overrides и чужие hooks при этом не копируются.

**Permissions on машина: текущий режим** и **Change…** у аккаунта задают режим на выбранной машине: **Default — use provider settings**
либо **Bypass permission prompts**. Режим применяется при старте и resume, текущие
сессии продолжают работу как раньше. Codex использует полный доступ без sandbox,
Claude — `bypassPermissions`, Kimi — **Never Ask** (`--auto`, включая автоматические
решения вопросов и планов), DeepSeek — родной preset `danger-full-access`.
Явный режим в аргументах запуска имеет приоритет над настройкой аккаунта.
Настройка не переносится вместе с авторизацией на другую машину. В режиме провайдера
DSH сохраняет родные настройки возобновляемой сессии. Старый работающий DSH host
потребует обновления адаптера после закрытия его сессий для применения bypass.
CLI: `hgs [@host] account permissions ID --mode provider|bypass`.
Список аккаунтов показывает **Default**, красный **Bypass** или **Varies**, если
настройки машин отличаются. Codex, Claude и Kimi также учитывают наследуемые
настройки профиля; подсказка показывает источник. Это настройки запуска аккаунта,
а не обещание режима каждой работающей сессии: настройки проекта и явные аргументы
могут отличаться. Непроверенные настройки провайдера явно отмечены в подсказке.


Временный нативный профиль без прочитанной идентичности не появляется на главной
как дополнительный Default account; его состояние доступно в Manage accounts.
Частичное обновление квоты сохраняет последнюю подтверждённую идентичность только
при неизменных credentials; выход и смена авторизации сбрасывают эту привязку.

Карточки **Attention & in progress** на главной используют тот же вид, что и список
сессий: состояние с таймером, проект и ветка, последнее действие, модель и усилие,
провайдер и машина. Счётчик сабагентов остаётся компактным; нажатие открывает
сессию, где можно раскрыть их список. Обновление данных сохраняет карточки и фокус.

В панели аккаунта машины, состояние входа и текущие разрешения собраны в один блок.
**+ Add to имя машины → Copy existing sign-in over SSH** переносит авторизацию Codex/Kimi
в новый профиль, без замены существующего. Диалог показывает источник и назначение;
переносятся только credentials и необходимые настройки провайдера/модели, без
истории, инструментов и hooks. Системный Keychain Claude не переносится: нужен вход
на целевой машине. Провайдер может потребовать повторный вход и после копирования.
**Remove from имя машины…** запрашивает подтверждение с названием аккаунта и машины.
Удаление из каталога выбранной машины отражается во всех подключённых к ней Zerus,
включая Zerus на самой машине. Файлы авторизации и существующие сессии сохраняются,
профили на остальных машинах остаются доступны. Удалённые из каталога профили не появляются
снова при опросе и не предлагаются в New session. Для возврата используйте обычный
**Add account**: выберите машину, провайдера и сохранённый аккаунт. Повторный вход
не требуется. **+ Add to имя машины** также предлагает сохранённый вход, если
на целевой машине найден тот же аккаунт; одноимённые аккаунты с другой
подтверждённой идентичностью не смешиваются. Сообщения об изменениях показываются в нижней строке статуса и исчезают;
при переключении аккаунтов прежнее сообщение об успешном переименовании не повторяется.
Кредиты показываются с двумя знаками после запятой.

**Sign in on имя машины…** открывает вход в CLI выбранного агента в терминале
указанной машины. Для авторизованного аккаунта или истёкшего входа подпись —
**Sign in again on имя машины…**: завершение входа обновляет авторизацию этого профиля.
Для DeepSeek **Set API key on имя машины…** открывает поле ключа прямо в Zerus.
Кнопка **Save on имя машины** сохраняет ключ через штатный credentials service
DeepSeek на указанной машине; для удалённой машины используется SSH.
Ключ передаётся через stdin, без аргументов командной строки и открытия браузера.
**+ Add to имя машины** использует сохранённый вход того же аккаунта, если он есть,
иначе предлагает то же поле; сохранение также возвращает удалённый
нативный профиль в каталог назначения. Установка предлагается только при отсутствии агента.
После сохранения отображается **API key configured**, а кнопка меняется на
**Change API key on имя машины…**. Этот статус подтверждает настройку ключа,
без платного запроса к модели. Расход API доступен в кабинете DeepSeek.
Для ключей из штатного файла одинаковый непрозрачный отпечаток объединяет аккаунт
на разных машинах; сами ключи в каталог и данные интерфейса не возвращаются.
Отсутствие входа в подписку DeepSeek не блокирует подключение через API-ключ.

Обновление Accounts сохраняет строки, выделение и прокрутку списка. Кнопка Refresh
вращается, а счётчик показывает оставшиеся запросы до завершения обновления
каталогов и данных аккаунтов; прежние значения остаются видимыми.

Если агент отсутствует, **Install agent…** открывает установку в терминале выбранной
машины (`hgs [@host] account install codex|claude|kimi|dsh`). Codex устанавливается
через [официальный npm-пакет](https://help.openai.com/en/articles/11096431),
Claude и Kimi — через их официальные установщики
([Claude](https://support.claude.com/en/articles/14552382-your-first-day-in-claude-code),
[Kimi](https://www.kimi.com/code/docs/en/)). Для DeepSeek используется версия,
поддерживаемая адаптером HGS. После установки обнови Accounts и выбери **Sign in…**.
Сам просмотр аккаунтов ничего не устанавливает и не переносит авторизацию.

В **Session → Details → Session usage** показан расход текущей нативной беседы:
входные и выходные токены, чтение/запись кэша, reasoning и дополнительные счётчики,
если они присутствуют в её истории. Текущий контекст отделён от накопленного расхода.
В **Activity** над полем ввода справа также показано `22% (217k/1M)`:
процент заполнения, использованные токены и размер окна. Точные числа доступны
при наведении; нажатие открывает статистику в Details. Цвет меняется на оранжевый
от 70%, на красный от 90%. Если размер окна не сообщён, процент не вычисляется.
У Kimi размер окна берётся из `max_context_size` точного активного model alias
в родной конфигурации аккаунта; лимит выходных токенов для этого не используется.
Codex использует `token_count`, Claude — usage ответов с дедупликацией по message ID,
Kimi — `usage.record`, официальный DSH — `tokenUsage` и `contextPressure`.
Для Claude также читается сохранённый `cost-state`: родная оценка стоимости,
время API/инструментов и изменённые строки. Устаревший снимок стоимости отмечается.
Кэш входит во входные токены, reasoning — в выходные, поэтому повторно к итогу
они не прибавляются. Расход дочерних агентов не суммируется с родителем.
Для отсутствующих данных и стоимости показано Not reported; стоимость по тарифам
HGS не вычисляет. Локальный кэш счётчиков читает только добавленный хвост истории.

```bash
hgs account ls
hgs @mac account add work --provider codex --label Work
hgs @mac account login work
hgs @mac codex /path/to/project --new --account work
hgs account copy native-codex --from @local --to mac --as codex-work --label Work
```

### Строка статуса

Сообщения об операциях показываются в общей нижней строке статуса постоянной
высоты: обновления не сдвигают содержимое окна. Обычный статус очищается через
пять секунд, ошибка остаётся до следующего сообщения. Полный текст доступен
по наведению на строку.

Недоступность машины показывается отдельно и остаётся до восстановления связи:
имя машины, причина ошибки локального опроса или SSH и состояние автоматической
повторной попытки. **Retry now** запускает опрос сразу. Во время подключения причина
не пропадает; уведомления об операциях её не заменяют. Опросы одной машины не
накладываются друг на друга.

### Поиск по содержимому

Поле над списком ищет имена, папки, ветки и модели сразу; от двух символов дополнительно
ищет публичные сообщения Codex, Claude и Kimi и сохранённые события инструментов.
Каждая машина ищет локально, через SSH возвращаются совпадения. В результатах видны
сессия, автор, дата и фрагмент с подсветкой. Выбор открывает найденное сообщение в
Activity; **Back to latest activity** возвращает текущую ленту. Escape очищает поиск.
Поиск по всем сессиям включает архив; фильтры состояния и машины сужают результаты.

Поиск использует сохранённые журналы, без скрытого reasoning и системных инструкций.
Для отзывчивости ограничены объём прочитанных файлов и количество результатов;
**Limited history searched** обозначает неполное покрытие очень больших журналов,
а **Some history unavailable** — недоступные файлы или машины. Такие результаты
не выдаются за полную историю. Длинное найденное сообщение явно помечается как excerpt.

### Модель, effort и форки

Модель и reasoning effort видны в списке и краткой шапке. Внизу Activity кнопка
**model  effort ⌄** открывает выбор модели и её уровней reasoning. В новой
сессии Codex/Kimi это работает **до первого сообщения**, когда нативный клиент
уже показывает пустое приглашение, но ещё не создал ID разговора. Проверяются
точный запуск и процесс; черновик, стартовый вопрос, неподтверждённый resume
или уже отправленное первое сообщение блокируют изменение. Для выбора модели
HGS не отправляет сообщение и не меняет defaults аккаунта. Для Codex/Kimi
варианты читаются из каталога выбранного аккаунта. В готовой сессии изменение
применяется через родное меню агента с подтверждением результата и проверкой
пустого терминального ввода. Глобальные настройки провайдера не меняются.

У занятой сессии выбор сохраняется с отметкой **Pending**: Zerus применяет его,
когда агент готов, в том числе после переключения на другую сессию. Сообщение,
отправленное до применения, использует текущую модель. Следующая отправка из HGS
в готовую сессию также применяет ожидающее изменение. У остановленной сессии
**Save for resume** сохраняет настройки для следующего явного возобновления и
не запускает агента. Более новый выбор с другого устройства не заменяется старым
отложенным запросом. CLI: `hgs [@host] settings <session> --json`.

Claude и неизвестные состояния пока управляются через Terminal: селектор показывает
причину, а не выдумывает доступные модели или значения. Для архивной сессии сначала
нужно выполнить Restore.

**Fork session…** в меню ⋯ и по ПКМ создаёт независимую беседу с сохранённым контекстом
в той же рабочей папке. Имя предлагается автоматически; новая сессия появляется
рядом с исходной в её группе. CLI: `hgs [@host] fork <session> [-n name] [-d]`
(для архива — `--archive ID`). Исходная беседа сохраняется; файлы рабочей папки общие.

Для установки GUI без перезапуска открытого окна и потери несохранённых черновиков:
`HGS_TRAY_RESTART=0 ./tray/install.sh`. Новая версия интерфейса откроется при следующем
запуске Zerus; обновлённый CLI начинает работать сразу.

### Activity, сообщения и встроенный Terminal

**Jump to latest** находится в центре строки под историей, рядом с **Mark as read**
и показателем контекста. Появление кнопки не уменьшает область сообщений
и не сдвигает место чтения.

Вложенный `codex exec`, унаследовавший HGS-переменные, регистрируется как дочерний
агент по подтверждённому `source: exec` в заголовке его журнала. Он не меняет
conversation ID и журнал основной сессии. Обычные `/new` и `/clear` продолжают
переключать основной диалог. Публичные commentary-сообщения Codex сохраняют свою
фазу при чтении обеих форматов журнала и не подменяют пустое событие завершения.

**Activity** и **Terminal** занимают основную рабочую область. Кнопка панели справа
от вкладок открывает инспектор **Tasks & agents / Details**. Эта же кнопка остаётся
на правом краю шапки инспектора и сворачивает его. Панель отделена фоном и тонкой рамкой.
Ширина меняется перетаскиванием разделителя. Ширина, выбранная вкладка и открытое
состояние сохраняются. Переключение инспектора не меняет основную вкладку, черновик
сообщения или подключение терминала.

В инспекторе показаны списки из успешных `TodoWrite`, `TodoList`, `SetTodoList`, `update_plan`,
`TaskCreate`, `TaskUpdate` и `TaskList`, когда провайдер передаёт их через hooks.
Учитываются состояния «запланировано / в работе / готово» и число завершённых пунктов.
Личные планы разделены по ID агента; общие Claude Task-списки сохраняют назначенного
исполнителя. Ошибка инструмента не обновляет план, Stop не завершает задачи.
Старые снимки помечаются **Last recorded**. До первого обновления списка после
установки показывается отсутствие данных; история планов задним числом не достраивается.
Хранятся до 100 пунктов на список и до 65 списков, с явной отметкой усечения.
`TaskList` Kimi перечисляет фоновые работы и не перезаписывает чеклист плана Claude.
Контракт успешного `PostToolUse` описан в документации
[Claude](https://code.claude.com/docs/en/hooks#posttooluse) и
[Kimi](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/hooks.html).

Цели Codex, Claude Code, Kimi Code и официального DeepSeek Harness показаны
над рабочей областью и в инспекторе. `Ready` завершает ответ, но не долгую цель.
Codex читается из `goals_1.sqlite`, Claude — из `goal_status` точного transcript,
Kimi Code 2.1.1 — из событий `goal.create/update/clear` родного wire-журнала.
Чтение не меняет состояние агента; показываются только записанные расход и лимиты.
У Claude доступны последний verdict и число проверок; временная пауза между проверками
может отсутствовать в истории. У DeepSeek отдельно видны фаза и разрешение
автопродолжения: после восстановления цель может ожидать явного возобновления.
Недоступный или несовместимый источник не заменяется выдуманной целью из промпта.

Имена подагентов открывают их собственную Activity с кнопкой **Main activity**.
Основной черновик сохраняется. История привязана к конкретным родителю и дочернему
агенту; доступен просмотр публичных сообщений и событий инструментов. Если провайдер
сохранил только последний результат или группы профилей, интерфейс сообщает об этом.
Промежуточные публичные сообщения Codex и Claude также читаются из родной истории,
поэтому они видны до завершения хода; внутреннее reasoning не отображается.

Результаты и обычные ошибки подагентов относятся к работе основного агента: они
сохраняются в дочерней Activity, но не создают непрочитанные уведомления и не входят
в счётчик внимания. Запросы ввода или подтверждения от подагента остаются видимыми.

При наличии внимания аватар Зеруса плавно раскручивается, делает оборот за 1,4 секунды
и останавливается на 1,6 секунды; цвет внимания пульсирует вместе с вращением.
Знак рисуется из кэша с учётом частоты экрана (цель 60–120 кадров/с), без замены
иконки кнопки на каждом кадре. В паузах и скрытом или свёрнутом окне таймер не обновляет рисунок.
В режиме уменьшенной анимации значок неподвижен. Кнопка **Sessions** показывает
общий счётчик независимо от фильтра. Прочтение и
**Mark all as read** убирают уведомления о результатах; неотвеченные вопросы остаются.
Повторное нажатие **Sessions** очищает поиск и фильтры и показывает все сессии.

В **Activity** сообщения пользователя и агента показаны отдельными карточками.
Твои сообщения сохраняют исходный текст: `>`, номера, Markdown-маркеры, отступы и
переносы строк видны как при вводе, в том числе в очереди, истории и поиске.
Ответы агента отображаются с Markdown, списками и кодом. Соседние события инструментов
собираются в компактные раскрываемые группы. Журнал открывается у последних событий и следует за новыми,
пока ты находишься внизу. При чтении истории сохраняются позиция и выделение;
кнопка **Jump to latest** возвращает к новым событиям. Это записанные hook-события
и доступные фрагменты сообщений, а не полная копия истории провайдера.
Порядок ленты: запрос → работа инструментов → ответ. Запрос Kimi из `TurnStarted`
тоже отображается сообщением; пустой служебный `UserPromptSubmit` перед ним скрыт.
Если для сохранённого фрагмента нет события в журнале,
он показан отдельным контекстом перед лентой, без выдуманного времени отправки.

Ссылки на файлы в ответах агента сохраняют подпись и видимый путь. Клик открывает карточку ссылки:
можно скопировать путь, открыть локальный файл или его папку. Относительный путь
считается от рабочей папки сессии. Для удалённого файла указана его машина и доступен
переход в её SSH-терминал; путь удалённой машины не открывается как локальный.
Номер строки сохраняется в карточке отдельно. Простое отображение ссылки ничего
не загружает и не запускает.

Под лентой находится поле сообщения: **Enter** отправляет, **Shift+Enter** добавляет
строку, **Esc** снимает фокус, сохраняя черновик. Можно вставить изображение,
перетащить локальные файлы или выбрать их через кнопку со скрепкой. На месте курсора
появляется `[Image #1]` или `[File #2]`, тот же ярлык показан у миниатюры. Ярлыки можно
перемещать вместе с текстом: порядок сохраняется при отправке, номера остальных
вложений при удалении не меняются. Черновики и вложения сохраняются отдельно для каждой сессии, пока открыт
Zerus, в том числе при переключении между машинами. При ошибке содержимое остаётся
в поле; успешная фоновая отправка не очищает черновик другой сессии.
У неотправленной карточки есть **Retry** и **Delete**. Повтор сохраняет другой
черновик и отправляет исходный текст с вложениями; удаление убирает только карточку
из Activity. Если тот же текст позднее отправлен через Terminal, старая ошибка
убирается автоматически. При неизвестном результате доставки доступно
**Check Terminal** вместо прямого повтора.

Сообщения можно отправлять и в **Ready**, и во время работы Codex, Claude и Kimi.
Они передаются в обычное поле ввода агента: провайдер сам обрабатывает следующее
сообщение или ставит его в очередь. Обычная отправка не посылает клавиши прерывания.
**Submitted to terminal** подтверждает только передачу текста; **Sent** в Activity —
нативное событие приёма. Видимая очередь отображается отдельным блоком **Queued in agent**.
Кнопка **Send now** вызывает подтверждённое сочетание провайдера, без повторной
вставки сообщения: Claude `Ctrl+X Ctrl+S`, Kimi `Ctrl+S`, Codex `Esc` для ожидающих
steer-сообщений (прерывает текущий шаг). Произвольные переназначенные сочетания,
обычные Codex follow-up очереди без команды немедленной отправки и неизвестные
интерфейсы остаются в Terminal. Кнопка недоступна при черновике, диалоге, compaction
или изменившейся очереди; CLI повторно проверяет запуск и снимок очереди.
CLI: `hgs [@host] send-now SESSION --json` с идентификаторами запуска, разговора и очереди.
CLI повторно проверяет конкретный запуск, процесс, tmux-pane и пустую область ввода:
он не заменяет набранный в терминале текст, не отвечает на запрос разрешения и не
запускает остановленного агента. При открытом диалоге, чужом черновике или неизвестном
состоянии отправка отклоняется, а текст остаётся в Zerus.
После ошибки провайдера (например, нехватки capacity или лимита) отправка снова
доступна, когда CLI подтверждает готовность обычного поля ввода в терминале.
Статус ошибки остаётся видимым до следующего события работы агента.
После **Turn interrupted** действует такая же проверка: **Send** становится доступна,
когда подтверждены прежний запуск и пустое родное поле ввода. HGS не ждёт нового
события от уже остановленного хода и не стирает запись о прерывании. Черновик
в Terminal, открытый диалог и неподтверждённый предыдущий ввод блокируют отправку.
В новой сессии Codex событие начала разговора может прийти только после первого
сообщения. HGS допускает этот первый ввод до события, если подтверждены новый запуск,
его процесс и пустое родное поле ввода. Экран входа/пароля всё ещё требует Terminal;
после его завершения доступность обновляется автоматически. До первого сообщения
модель и effort берутся из видимой строки состояния провайдера, когда её можно
однозначно распознать. Enter при недоступной отправке показывает причину.
Для интерактивного ответа, slash-команд и произвольного ввода используй **Terminal**.

Необязательные вопросы Codex (`request_user_input_async`) появляются в Activity с пометкой
**Optional question**, вариантами ответа, свободным вводом и **Skip**. Обычное поле
сообщения остаётся доступным. Карточка сохраняется до ответа или пропуска, включая
ответ из терминала; подтверждение `accepted` от инструмента не считается ответом.
Skip убирает вопрос без отправки выдуманного ответа. Ответ отправляется с точным
нативным ID вопроса; существующий черновик в Terminal не перезаписывается.

Вопросы **AskUserQuestion** показываются отдельной формой в Activity: вкладки вопросов,
варианты ответа, несколько вариантов при `multi_select` и собственный ответ **Other**.
Выбор сохраняется при переключении сессий. **Submit answers** отправляет всю форму
именно в ожидающий инструмент; обычное поле сообщения на это время заменяется формой.
В Kimi 2.1.1 форма работает и для уже открытых сессий: HGS читает структурированный
запрос из журнала Kimi, проверяет конкретный запуск и текущее окно вопроса, передаёт
выбор через tmux и ждёт подтверждения ответа в журнале провайдера. Неподдерживаемые
интерактивные запросы остаются доступны через **Open Terminal**.
В Claude форма тоже отправляет ответы: HGS сверяет вопрос и варианты в родном
терминале, заполняет вкладки и проверяет итоговый список перед подтверждением.
Поддерживаются несколько вариантов и собственный текст Other. Успех подтверждает
точный результат AskUserQuestion в журнале этого разговора. Незавершённый чужой
черновик Other сохраняется; устаревший вопрос или неподтверждённая доставка не
вызывают автоматической повторной отправки. Проверено на Claude Code 2.1.284/2.1.289.
Необязательные вопросы Codex `request_user_input_async` тоже доступны в Activity:
можно выбрать вариант, написать свой ответ или нажать **Skip**. Обычное поле
сообщения остаётся доступным. Успешное создание вопроса не считается ответом;
Skip скрывает именно этот вопрос, не отправляя выдуманного ответа агенту.
Вопросы восстанавливаются из всего журнала точной беседы, затем читаются только
добавленные записи. Старый неотвеченный вопрос не теряется за пределами хвоста
сообщений; новым необязательным вопросам отдаётся приоритет перед старыми.
Ошибка чтения вопросов показывается отдельно и не скрывает остальные сообщения.
В карточке видны дата и время вопроса в местном часовом поясе и **N pending** —
общее число ожидающих вопросов, включая текущую карточку. Многочастный запрос
считается по числу вопросов в нём. Если провайдер не сообщил время (например,
для стартового запроса доверия), дата скрыта; время опроса вместо неё не подставляется.
Если ожидают несколько необязательных запросов, стрелки рядом со счётчиком позволяют
выбрать любой из них (от новых к старым). Черновики и открытая часть многочастного
запроса сохраняются. Заголовок показывает позицию, например **Optional question #3/17**.
Обновления не сбрасывают выбранный стрелками вопрос;
обязательное подтверждение временно получает приоритет и скрывает стрелки.
Другие неподдерживаемые диалоги Codex остаются во вкладке Terminal.
Подтверждённые ответы сохраняются в Activity отдельными сообщениями **You (answer)**.

Стартовый вопрос Claude **Make auto mode your default permission mode?**
тоже отображается в Activity, включая полный текст и оба родных варианта ответа.
Он распознаётся и после `SessionStart`, когда Claude уже сообщил ID разговора,
но ещё ожидает выбор режима. В списке сессий показывается **Needs approval**;
сообщения заблокированы до ответа. Zerus не выбирает подсвеченный вариант автоматически.
Ответ привязан к текущему запуску, процессу и неизменившемуся диалогу.

Стартовый запрос Claude **Accessing workspace:** появляется в Activity как
**Needs approval**, даже до создания ID беседы. Карточка сохраняет путь и весь
показанный Claude текст предупреждений о разрешениях, включая пометки об
укороченном списке. **No, exit** завершает запуск; **Yes, I trust this folder**
передаёт подтверждение в native Claude. Выбор не сделан заранее; устаревший
запрос, другая папка или сменившийся процесс не принимают ответ.

Стартовый запрос Codex **Folder access / Trust this folder?** доступен в Activity
до создания беседы. Карточка показывает точную папку, предупреждение Codex и варианты
**Trust and continue** / **Quit**, без заранее выбранного ответа. Она появляется
только для полного распознанного экрана в том же живом процессе и запуске;
подмена папки или изменение предупреждения отменяют ответ. Пропустить обязательное
решение о доверии нельзя: **Quit** завершает этот запуск без выдачи доверия.

Стартовый запрос Kimi **Trust this folder?** тоже появляется в Activity и помечает
сессию как требующую внимания. Карточка показывает папку и полный видимый список
MCP-серверов с командами запуска. Выбор **Trust this folder** разрешает их запуск
и запоминает доверие в Kimi; **Don't trust** завершает Kimi. В Zerus ответ заранее
не выбран. Проверяются запуск, процесс, папка и неизменность всего запроса перед
каждой клавишей; неподдерживаемый или обрезанный экран нужно обработать в Terminal.
Этот запрос поддерживается до создания разговора: пустой `conversation_id`
разрешён только для проверенных стартовых запросов доверия и выбора режима Claude.

`inspect` возвращает массив `pending_questions` с `question_id`, `question_hash`,
`run_id`, `conversation_id`, вопросами и признаком `can_answer`. Для внешнего клиента
есть `hgs [@host] answer <session> --json`: stdin содержит `request_id` (UUID),
`question_id`, `expected_question_hash`, `expected_run_id`, `expected_conversation_id`
и `answers` — массив `{question_id, selected_option_ids, text}`. Ответ `status: answered`
выдаётся после подтверждения провайдера. Устаревший вопрос отклоняется; при обрыве
доставки автоматического повтора нет, выбранные ответы остаются в форме.

Вложения передаются на машину агента через stdin/SSH и сохраняются в закрытом
каталоге состояния HGS (каталог `0700`, файлы `0600`). Терминальный агент получает
пути и просьбу прочитать файл или посмотреть изображение прямо рядом с ярлыком
в тексте. DeepSeek получает чередующиеся текстовые и нативные блоки изображений.
Если ярлык стёрт, но файл остался прикреплён, вложение добавляется в конец сообщения.
Лимиты: текст 64 KiB, до 8 файлов, 10 MiB на файл и 20 MiB на сообщение.
В Activity вложение отображается как файл на месте отправки сообщения; у изображений
есть миниатюра. По клику файл сразу открывается в приложении по умолчанию.
Файлы удалённой сессии загружаются с её машины и кешируются; сохранённые квитанции
позволяют открыть вложения после перезапуска Zerus. Если исходный файл удалён,
ошибка появляется в строке статуса. Загрузка миниатюр не сдвигает ленту и ограничена
тремя одновременными запросами; открытие файла имеет приоритет перед фоновыми загрузками.

Диалог Kimi о протухшем кэше после простоя также появляется в Activity и переводит
сессию в **Needs attention**. Доступны четыре родных варианта: сжать контекст,
начать новую сессию, продолжить с полной историей или отключить напоминание.
HGS проверяет активный диалог перед каждой клавишей и не выбирает вариант сам.
После выбора отложенное сообщение продолжает обрабатывать сам Kimi; повторной
отправки текста со стороны Zerus нет.
Во время сжатия контекста в Activity видна строка **Compacting context…** с
плавным индикатором с циклом 3,2 секунды. Она следует за состоянием провайдера, исчезает после
завершения и не перерисовывает историю сообщений при обновлениях.
На карточке сессии в это время показано **Compacting (1m 23s)**: отдельный таймер
от начала сжатия. Повторное событие начала и сообщение, поставленное в очередь,
не сбрасывают его. После сжатия возвращается **Working** с общим временем работы.

Вкладка **Terminal** подключает настоящий PTY-клиент к существующей tmux-сессии,
локально или через SSH. Поддерживаются ANSI/VT, цвета, UTF-8, полноэкранные приложения,
клавиши, выделение, прокрутка истории, вставка и изменение размера. **Connect** /
**Disconnect** и **Reconnect** управляют только этим подключением. Закрытие окна
отсоединяет клиент; агент продолжает работать. Переключение на другую сессию
не переиспользует её старый ввод. Кнопка **Open externally** открывает привычный
внешний терминал, а меню сессии сохраняет **Copy connect command**.
Пункт **Open folder** в меню открывает папку локальной сессии в файловом менеджере,
сохраняя выбранную сессию в Activity.

Встроенный клиент использует `hgs a <session> --existing [--run-id ID]`: пропавшая
сессия не возобновляется автоматически. Обычный `hgs a <session>` сохраняет прежнее
поведение восстановления Saved. Движок терминала — vendored **libvterm 0.3.3**
(MIT, исходники и сведения о версии в `tray/vendor/libvterm`); сборка не скачивает
дополнительные зависимости из сети.

Отрисовка обновляет только изменившиеся ячейки и область курсора. Мигание курсора
и небольшой новый вывод не запускают обход всей сетки большого Retina-окна.

### Логические проекты — раздел Projects

ПКМ в свободной области списка проектов открывает **New project…**. Этот пункт
также доступен в меню самого проекта перед действиями изменения порядка.

Проект имеет стабильный ID, название, цвет и набор папок на разных компьютерах.
Одна физическая папка может входить в несколько проектов. Сессия принадлежит
ровно одному проекту; перенос через меню или перетаскивание меняет принадлежность,
сохраняя рабочую папку и процесс агента. Дочерние агенты остаются внутри сессии.

**Projects** позволяет создавать и переименовывать проекты, выбирать любой RGB-цвет,
добавлять и убирать папки. Цвет применяется к заливке заголовка проекта: доступны
яркий и мягкий варианты, предпросмотр, Apply и Cancel. Компьютеры в списке папок
показаны цветными лейблами. Для папки указываются компьютер, путь и необязательное
название. **Browse…** использует системный диалог локально и браузер по SSH удалённо.
В списке **Projects** порядок меняется перетаскиванием, через ПКМ → Move project up/down
или Alt+↑/↓. Он сохраняется и применяется также в списке сессий. Проект по умолчанию
помечен **Default** на плашке списка и в цветном предпросмотре.
Параметры проекта занимают компактный блок сверху. Имя и копируемый ID показаны
одной строкой; поле имени ограничено по ширине. Без выбранной папки таблица
заполняет свободную высоту; при выборе папки ниже появляется каталог worktree.

В **New session** проект, компьютер и рабочая папка показаны отдельными полями.
При открытии папка подставляется из выбранного проекта для указанного компьютера;
если подходящих папок нет, поле остаётся пустым. Папка другого проекта по умолчанию
не переносится в новую форму. Явный запуск из папки или worktree сохраняет её путь.
Смена проекта сохраняет компьютер. Папка следует выбранному проекту, кроме пути,
указанного через **Browse…** в этом окне: такой путь запоминается отдельно для каждой
машины до закрытия диалога. Выбор другой папки из списка отменяет это закрепление;
автоподстановка и выбор worktree сами по себе его не включают.
Если папка не входит в выбранный проект, под ней
появляется янтарное предупреждение: запуск добавит её в этот проект. Смена
проекта сама по себе папки не добавляет. При возвращении в проект, где папка
уже есть, предупреждение исчезает; offline-машина не заменяется другой.
На экране **Projects** выберите папку и нажмите **New session…** над таблицей
или в её меню по ПКМ. Проект, компьютер и точная папка сразу подставляются в форму;
агента и аккаунт можно выбрать перед запуском.
Полный путь и принадлежность проекту находятся под выбором папки. **Browse…** позволяет
выбрать любой локальный или удалённый каталог, даже если в проекте пока нет папок.
Новый каталог добавляется в проект только после появления успешно запущенной сессии
с соответствующим идентификатором запуска; отмена и ошибка ничего не добавляют.
**Folders…** рядом с проектом открывает управление его папками. **Open terminal window**
по умолчанию выключена, последний выбор запоминается. DeepSeek использует встроенный Native UI.
**Terminate session** останавливает отслеживаемую сессию Codex/Claude/Kimi и переносит
её запись в **Archive**, сохраняя историю, аккаунт, папку и проект. Возврат — через
**Restore**. Записанные ошибки и незавершённый старт также можно архивировать; если
подтверждённой истории нет, восстановление недоступно. **Forget** удаляет запись из
каталога отдельно. CLI: `hgs terminate <session> [--expected-run-id ID]`; прежний
`hgs kill` сохраняет явную семантику удаления. Сессии без HGS tracking и native DeepSeek
пока не поддерживают этот архивный путь — диалог явно сообщает об этом.
При **Terminate session** карточка и заголовок сразу показывают **Terminating…**.
Повторные действия и отправка сообщений блокируются до подтверждения остановки;
запаздывающие опросы не возвращают старый статус. Ошибка остановки возвращает доступные
действия и показывает причину; новый запуск с тем же именем не наследует эту метку.

Проекты заменяют прежние группы. Миграция сохраняет ID, порядок и состав групп;
закреплённые сессии возвращаются в прежний проект либо в проект по умолчанию.
Прежний **Inbox** — обычный проект: его можно переименовать, заменить в качестве
проекта по умолчанию или удалить с переносом сессий. При удалении любого проекта
нужно выбрать проект для его сессий; файлы и процессы агентов сохраняются.
В новой установке проект по умолчанию называется **General**. Он принимает
сессии, запущенные вне Zerus, если их принадлежность ещё не задана.
Перед миграцией старая организация сохраняется в `workspace/organizationBeforeProjects`.
Данные проектов и папок хранятся в настройках этого экземпляра Zerus
(`workspace/organization`, версия схемы 2); автоматическая синхронизация настроек
между экземплярами не выполняется. Папки и сессии внутри одного проекта могут
находиться на любом из подключённых компьютеров.

Иконка **Open shell in session folder** в заголовке сессии и одноимённая команда
контекстного меню открывают обычный login shell в её рабочей папке. Для удалённой
сессии используются настройки SSH компьютера из Zerus.
Рядом находится **Open session folder in file manager**: она открывает рабочую
папку локальной сессии в системном файловом менеджере (Finder на macOS).
Для удалённого компьютера или недоступной папки кнопка отключена.

Агенты другого типа, запущенные с унаследованным окружением HGS, показываются
дочерними сессиями со своим провайдером и Activity. Проверены Kimi → Codex и
Codex → Kimi; их ID и модели не заменяют данные родителя. История таких CLI-запусков
доступна для чтения; продолжение диалога требует поддержки со стороны harness.

**Фокус на Wayland не гарантирован.** Окно открывается штатной парой
`show()` + `activateWindow()`, но у клиента без недавнего ввода композитор вправе не выдать
токен активации (та же xdg-activation, из-за которой не работает подъём окна Konsole, см.
ниже). Если окно открылось за другими или без фокуса — поднимите его из панели задач; со
стороны трея это не чинится.


### Установка на Linux

```bash
cd tray && ./install.sh
```

Собирает релизную сборку (`cmake` + `qt6-base` + `qt6-webengine` + `kstatusnotifieritem` + `kwindowsystem`, `build/`), ставит бинарь в
`~/.local/bin/hgs-tray`, systemd `--user`-юнит в `~/.config/systemd/user/hgs-tray.service`
и `.desktop` в `~/.local/share/applications/hgs-tray.desktop`, затем
`systemctl --user daemon-reload` и `enable --now`. Никакого `sudo`, весь путь — в `~/.local`
и `~/.config`. Идемпотентен: повторный запуск сверяет то, что уже стоит, с тем, что должно
быть, и не трогает уже запущенный процесс (`enable --now` — это `start`, а не `restart`, на
активном юните он no-op); печатает `Installed hgs-tray.`, только если реально что-то
поменял (по этой строке внешняя автоматизация может определить `changed`).

Автозапуск — **только** через systemd `--user`-юнит (`WantedBy=graphical-session.target`,
проверено на Plasma 6/Wayland: `graphical-session.target` в сессии реально достигается,
не просто объявлен). `.desktop`-файл ставится в `~/.local/share/applications/` — это пункт
меню приложений (можно найти и запустить трей руками из лаунчера KDE), а не автозапуск:
каталог автозапуска — `~/.config/autostart/`, и он в этот путь не попадает, так что ключи
`X-GNOME-Autostart-enabled`/`X-KDE-autostart-phase` в нём ни на что не влияют. Дублирующего
автостарта поэтому нет; второй ручной запуск (`~/.local/bin/hgs-tray`) в любом случае
безопасен — см. «Один экземпляр» ниже.

Если система не даёт трею подняться (нет апплета системного трея на панели), процесс
выходит с кодом 4; юнит это НЕ ретраит бесконечно (`RestartPreventExitStatus=4` в
`packaging/hgs-tray.service`) — это состояние рабочего стола, а не сбой, и раз в 5с оно
само не изменится. Настоящий крах (сегфолт, занятый сокет) по-прежнему поднимается сам.

### Установка на маке

```bash
./mac-install.sh mac        # с другой машины: возит tray/ на мак и зовёт там install.sh
cd tray && ./install.sh     # или на самом маке, если исходники уже там
```

Штатный путь — первый: чекаута репо на маке нет, `mac-install.sh` кладёт исходники в
`~/.local/src/hgs/tray` (там же остаётся `build/`, поэтому следующий прогон собирается
инкрементально) и запускает `install.sh` уже на маке. Это тот же скрипт, вторая ветка (`uname -s` = `Darwin`). Собирает релизный **`.app`-бандл**
(`cmake -DCMAKE_PREFIX_PATH="$(brew --prefix qt)"`, Qt6 из Homebrew) и кладёт ровно два
объекта:

| Что | Куда |
|---|---|
| бандл | `~/Applications/hgs-tray.app` |
| LaunchAgent | `~/Library/LaunchAgents/com.hgdev.hgs-tray.plist` |

Больше ничего: ни `sudo`, ни `/Applications`, ни `/opt`, ни `.desktop`. `tray.conf` скрипт
не создаёт — этот файл появляется, только если ты сам выберешь режим в меню трея.
Инструменты ищутся сначала в `PATH`, потом по штатным путям Homebrew (`/opt/homebrew/bin`,
`/usr/local/bin`): неинтерактивный ssh на мак приходит с голым
`PATH=/usr/bin:/bin:/usr/sbin:/sbin`, `brew shellenv` в таком не отрабатывает, — так скрипт
одинаково работает и по ssh, и из Терминала.

Автозапуск — LaunchAgent (`RunAtLoad`), но установка ещё и загружает его сразу
(`launchctl unload` + `launchctl load`), так что ни перезагрузка, ни перелогин не нужны.
Идемпотентность как на Linux: повторный прогон сравнивает **cdhash** установленного бандла
с только что собранным (побайтово сравнить нечем — в исполняемом файле лежит подпись, а в
`_CodeSignature/` её отпечатки), сверяет plist и **не трогает уже работающего агента**;
`Installed hgs-tray.` печатается, только если что-то реально поменялось.

Проверить, что агент работает, а не просто зарегистрирован:

```bash
launchctl list | grep com.hgdev.hgs-tray     # 4641	0	com.hgdev.hgs-tray
```

Первое поле — PID. `-` вместо PID означает «стартовал и умер», и тогда второе поле — код
его выхода: `4` = не нашлось строки меню (см. `KeepAlive` ниже), всё остальное — настоящий
сбой. Headless-проверка связки с `hgs`, без строки меню:

```bash
~/Applications/hgs-tray.app/Contents/MacOS/hgs-tray --selftest --hgs ~/.local/bin/hgs
```

**Снести целиком:**

```bash
launchctl unload ~/Library/LaunchAgents/com.hgdev.hgs-tray.plist
rm -f ~/Library/LaunchAgents/com.hgdev.hgs-tray.plist
rm -rf ~/Applications/hgs-tray.app
```

Это всё, что установка создала. Ни `~/.config/hgs/tray.conf` (если ты его завёл), ни сам
`hgs`, ни чужие LaunchAgent'ы это не трогает.

#### Ad-hoc-подпись: зачем и чем платишь

`install.sh` делает `codesign --force --deep --sign -` — подпись без сертификата. Это не
гигиена, а условие запуска: на macOS 26 launchd убивает приложение, у которого есть только
подпись от линковщика, — процесс не доживает до первой строки `main()`, в логе
`OS_REASON_CODESIGNING`. Подпись на уровне бандла привязывает `Info.plist` и запечатывает
ресурсы, и такое launchd принимает; соседний TrustTunnelAgent лечится ровно тем же и по той
же причине. Подписывается бандл в `build/` **до** копирования — тогда установленный равен
собранному, и cdhash-сравнение выше отвечает честно.

Цена известна заранее: подпись ad-hoc, то есть никем не заверенная. `amfid` вправе писать в
системный лог `signature not valid: -67050` на каждый запуск, а будущая macOS может
ужесточить проверку — тогда понадобится настоящий Developer ID и подпись на этапе сборки.
`codesign -dv ~/Applications/hgs-tray.app` показывает `Signature=adhoc` — так и должно быть.

#### plist: почему `--hgs` абсолютным путём и почему `KeepAlive` только после крэша

Шаблон — `packaging/com.hgdev.hgs-tray.plist`, `__APP__` и `__HGS__` подставляет
установщик: plist для launchd — данные, ни `~`, ни переменные окружения он в нём не
разворачивает.

- **`--hgs <абсолютный путь>` обязателен.** launchd запускает агента с голым
  `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, а `hgs` живёт в `~/.local/bin` — без явного пути
  трей на каждом тике опроса получает `FailedToStart` и показывает пустой флот. Установщик
  берёт `~/.local/bin/hgs`, иначе `command -v hgs`, а если нет ни того ни другого —
  **отказывается ставить** и говорит, что сделать: поставить `hgs` с рабочей машины
  (`./mac-install.sh mac`). Молча поставить заведомо неработающее хуже.
- **`--open-mode` в plist намеренно НЕ передаётся.** Незнакомое или чужое значение в
  командной строке — фатальная ошибка запуска (код 2, см. раздел `--open-mode`), так что
  протухшее значение в plist означало бы агента, который вообще никогда не стартует. То же
  значение в `tray.conf` — всего лишь предупреждение и откат на умолчание. Пусть решает
  файл.
- **`KeepAlive` = `{Crashed: true}`**, а не `true` и не `false`. У launchd нет аналога
  systemd'шного `RestartPreventExitStatus=4`: с `KeepAlive=true` трей, штатно вышедший с
  кодом 4 (строки меню нет), крутился бы в бесконечном цикле. `Crashed` перезапускает
  только после смерти по сигналу крэша — а это ровно `abort()` сторожа главного потока
  (см. следующий раздел), которым трей вылезает из дедлока AppKit. Обычный выход, «Quit»
  из меню и `launchctl unload` перезапуска не дают; поднять руками по-прежнему можно
  `launchctl kickstart -k gui/$(id -u)/com.hgdev.hgs-tray`.
- **`StandardErrorPath`** = `~/Library/Logs/hgs-tray.log` (путь подставляет установщик):
  варнинги Qt и строка сторожа перед `abort()`. Без него stderr агента уходит в никуда, и
  зависание не оставляет ни следа.

#### Зависание в AppKit на macOS 26: как выглядит, как лечится, что сделано

Симптом: иконка в строке меню есть, клик по ней не делает ничего, процесс жив с 0% CPU.
Живой случай 2026-09-14 (macOS 26.6.1, Qt 6.11.1): трей повис во время работы с меню и
шесть дней молча висел в строке меню. Главный поток стоял в AppKit/FrontBoardServices:
`NSStatusBarButtonCell drawWithFrame` → `NSStatusItemScene updateSettings` → `FBSScene
_updateClientSettings` → `BSServiceDispatchQueue performAsyncAndWait` → вечное ожидание
владения очередью, других потоков в процессе нет. Самоблокировка AppKit, наших кадров в
стеке нет; та же сигнатура у чужого приложения — stablyai/orca#17045 (macOS 26.5.1).

Диагностика по ssh, без sudo:

```bash
launchctl list | grep com.hgdev.hgs-tray                 # PID и код последнего выхода
sample "$(pgrep -x hgs-tray)" 1 -mayDie -file /tmp/t.txt  # стек всех потоков
grep -c wait_for_ownership /tmp/t.txt                     # >0 у главного потока = оно
```

Косвенный признак с рабочей машины: трей мака опрашивает арч раз в минуту по ssh, так
что ровная минутная гребёнка `Accepted publickey` в `journalctl -u sshd` на арче — живой
главный поток, а обрыв гребёнки — момент зависания.

Что сделано в трее, чтобы это случалось как можно реже, а случившись — само лечилось:

- **`QuietTrayIcon`** (только на маке) не дёргает `NSStatusItem` без изменений и не
  трогает его вовсе, пока открыто меню. До этого иконка и тултип переписывались на каждом
  2-секундном тике — ~43 000 обращений к FrontBoard в сутки, — а при открытом меню каждое
  из них было перерисовкой подсвеченной кнопки, то есть ровно тем путём, где висит AppKit.
  Ради этого `IconFactory` мемоизирует плитки (одинаковый вид → тот же `QIcon`), а возраст
  опроса в тултипе идёт в минутах, а не в секундах.
- **`MainThreadWatchdog`** (на обеих платформах): если главный поток полминуты не крутит
  цикл событий, отдельный поток пишет строку в stderr и делает `abort()`. Крэш поднимает
  launchd (`KeepAlive {Crashed}`) или systemd (`Restart=on-failure`), а крэш-репорт macOS
  показывает, где стоял главный поток.
- **`StandardErrorPath`** — чтобы у следующего такого случая был след.

#### Что на маке иначе

Два режима клика — `terminal` (по умолчанию) и `clipboard`; полностью они описаны в
разделе `--open-mode` ниже, здесь — только маковская специфика:

- **`terminal`** — `Terminal.app` через `osascript do script`: есть на любом маке, ставить
  нечего, но открывает **всегда новое окно**. Вкладку в уже открытом окне чистым AppleScript
  создать нельзя — в словаре `Terminal.app` элемент `tab` у окна объявлен `access="r"`.
- **`clipboard`** — единственный режим, одинаковый на обеих платформах, и единственный, где
  ни модалок, ни лишних окон.

##### Почему не Tabby

Третьим режимом был `tabby` (`tabby run <argv>` — настоящая новая вкладка). Он удалён
2026-08-28: команды `tabby` на маке **взять негде**, так что пункт меню никогда не мог
сделать обещанного. Проверено на живой машине (Tabby 1.0.235, Electron 38, macOS 26.6.1),
а не выведено из документации. Сам бандл `Tabby.app` не ставит никакого CLI («Shell
integration» в настройках Tabby — это Automator-workflow'ы для Finder, а не команда), а
оба способа позвать бинарь из бандла проверены и не работают:

- **симлинк на `Contents/MacOS/Tabby`** даёт Electron, запущенный по чужому пути: он не
  находит свои helper-app (`FATAL … Unable to find helper app`) и уходит в цикл падений
  GPU/network-процессов. Процесс не завершается — живёт минутами и снимается вручную.
- **прямой запуск `/Applications/Tabby.app/Contents/MacOS/Tabby run …`** поднимает
  **второй экземпляр** Tabby, разбор argv у которого падает внутри yargs/cliui
  (`mixin.stripAnsi is not a function`) ещё до того, как argv уедет в уже запущенный
  экземпляр. Вкладки нет, зато в Dock висит второй Tabby.

**Симлинк делать не надо.** Прошлые версии этого README его советовали — совет неверный:
следовать ему значит оставлять после каждого клика по сессии зависший Electron. Смысл
вернуть режим появится только вместе с настоящей командой `tabby` (починенный апстрим,
своя обёртка); тогда же вернётся и её собственная цена — модальное «Run "…"?» на **каждый**
запуск, то есть на каждый клик по сессии.

**Служебные подтверждения действий на маке идут через `osascript`.**
Уведомления **Needs attention** используют собственный обработчик Notification Center
с ожиданием системного разрешения и отдельной идентичностью для каждого клика.
Для остальных подтверждений сохранён прежний путь. Причина не в
красоте: `QSystemTrayIcon::showMessage()` на macOS 26 теряет **первое** сообщение
приложения. Разрешение на уведомления система спрашивает ровно в момент первой отправки,
и пока пользователь не ответил, само сообщение доставляется с пустой видимостью
(`visibility: []` в логе `usernoted`) — баннера нет; ответ «разрешить» приходит через
несколько секунд, а ещё через 12 секунд Qt по своему таймауту удаляет уведомление и из
истории. Итог — пользователь не видит ничего и не может найти потом, а первое сообщение
обычно и есть самое важное («открылось не так, как просили»). `display notification` из
`osascript` идёт от имени Script Editor, у которого разрешение есть всегда, поэтому видно
уже первое сообщение; цена — имя отправителя в баннере не «hgs zerus». Если `osascript`
не запустился, трей всё равно пробует балун Qt: невидимое уведомление плохо, но молчание
хуже. На Linux ничего не изменилось — там штатный `showMessage()`.

**Подъём уже приаттаченной сессии на маке не реализован.** Это не «не работает, как
xdg-activation на Wayland», а не написано вовсе: `MacBackend` не ищет окно по tty и не
поднимает его. Клик по сессии с `●` откроет второй клиент tmux на тот же экран.

Zerus стартует только в строке меню (`LSUIElement` в `packaging/Info.plist`). Когда
открыто окно приложения, он появляется в Dock и ⌘Tab с иконкой приложения; сворачивание
сохраняет его в списке. После закрытия последнего окна остаётся только строка меню.

### Флаги и конфиг

```
--hgs <path>          путь к бинарю hgs; по умолчанию ищется в PATH
--local-poll <ms>     период опроса своего бокса   [2000]
--peer-poll <ms>      период опроса пиров          [60000]
--terminal <tmpl>     шаблон запуска терминала, {cmd} подставляется командой
--icon-color <color>  ручной override цвета знака Z и бейджа (например "#ff0000")
--open-mode <mode>    что делает клик по сессии; набор зависит от платформы:
                      Linux — auto|tab|window|clipboard [auto],
                      macOS — terminal|clipboard [terminal],
                      см. ниже (то же самое переключается из меню трея)
--selftest            headless-проверка связи с hgs, без трея и без дисплея
--sessions            открыть окно менеджера сессий
```

Значения, не заданные в командной строке, читаются из `~/.config/hgs/tray.conf`
(`ключ=значение`: `hgs`, `local-poll`, `peer-poll`, `terminal`, `icon-color`,
`open-mode`) — командная строка всегда побеждает файл. Файла по умолчанию нет вовсе;
единственное, что создаёт и правит его сам трей, — переключатель «Open in» в меню
(см. ниже), и он сохраняет всё остальное содержимое дословно, включая твои комментарии.
`--selftest` не поднимает
`QApplication`/трей вообще: только запрашивает у `hgs` локальный JSON и печатает
`hgs ok: host=… sessions=… projects=…` или `hgs FAILED: …` — годится проверять по ssh,
без иксов/Wayland.

### Один экземпляр

Второй запуск не поднимает вторую иконку: стучится в сокет уже работающего трея и сразу
выходит с кодом 0, напечатав `hgs-tray: already running`. Актуально и для двух автозапусков
подряд (например, если systemd и `.desktop`-автозапуск когда-нибудь окажутся включены
одновременно) — второй просто тихо завершается, а не открывает второй значок.
С флагом `--sessions` он также поднимает окно менеджера в уже работающем процессе.

### Konsole: почему клик иногда открывает окно, а не вкладку

Konsole 26.08 держит `runCommand`/`sendText` по D-Bus за настройкой **`konsolerc`,
секция `[KonsoleWindow]`, ключ `EnableSecuritySensitiveDBusAPI`** (то же самое —
Settings → Configure Konsole → «Enable the security sensitive parts of the DBus API») —
и она **выключена по умолчанию**. Без неё Konsole отвечает `AccessDenied` на команду в
новую вкладку, поэтому трей не может ни создать вкладку, ни послать в неё `hgs a …`, и
падает назад на отдельное окно Konsole (`konsole -e bash -lc '…'`) — то самое окно
закрывается, когда ты отключаешься от tmux, в отличие от вкладки в уже открытом Konsole.
**Включи настройку — и клик станет открывать вкладку**, а не окно.

### `--open-mode`: вкладка, окно или буфер обмена — явный выбор, а не побочный эффект настройки

Откат на окно из предыдущего раздела раньше был единственным поведением и происходил
тихо. `--open-mode <режим>` (и `open-mode=` в `tray.conf`) делает это выбором. **Набор
режимов зависит от платформы** — терминалы у них разные, и предлагать на маке «вкладку
Konsole» было бы враньём:

| | режимы | по умолчанию |
|---|---|---|
| Linux | `auto`, `tab`, `window`, `clipboard` | `auto` |
| macOS | `terminal`, `clipboard` | `terminal` |

`clipboard` — единственный режим, общий для обеих: буфер обмена есть везде, а всё
остальное — имя конкретного терминала. Значение от **другой** платформы в `tray.conf`
(общие dotfiles, перенос домашнего каталога) трей не ломает: предупреждение в stderr и
режим по умолчанию, ровно как на любое другое незнакомое значение. В командной строке то
же значение — фатальная ошибка запуска с объяснением: `--open-mode` набирают руками
прямо сейчас, и молча сделать не то, что просили, хуже, чем не запуститься.

На Linux:

- **`auto`** (по умолчанию, прежнее поведение) — пробовать вкладку, тихо откатываясь на
  окно, если Konsole не отдаёт D-Bus API. Никаких уведомлений.
- **`tab`** — только вкладка. Если API выключен, трей **не** откатывается молча: он
  всё равно открывает окно (потерять клик было бы хуже, чем открыть не то, что просили),
  но показывает уведомление трея с точным указанием, что включить —
  `~/.config/konsolerc`, секция `[KonsoleWindow]`, ключ
  `EnableSecuritySensitiveDBusAPI=true`. Уведомление показывается один раз за прогон
  трея, а не на каждый клик — правило то же самое, а нажатий может быть много.
- **`window`** — всегда новое окно. `open()` в этом режиме вообще не обращается к
  D-Bus Konsole — ни одного вызова, даже пробы.
- **`clipboard`** — обычный клик по существующей сессии кладёт команду подключения
  (`hgs a claude/sample-project`, `hgs @mac a …`) в буфер обмена и подтверждает это
  уведомлением. Вставляешь сам в ту вкладку, которая нужна. Явные **Open terminal**
  и **New session** с включённой **Open terminal window** запускают терминал. См. отдельный раздел ниже.

На маке:

- **`terminal`** (по умолчанию) — `Terminal.app` через `osascript do script`. Есть на
  любом маке, ничего доустанавливать не надо, но открывает **всегда новое окно**: вкладку
  в уже открытом окне чистым AppleScript создать нельзя (в словаре `Terminal.app`
  элемент `tab` у окна объявлен `access="r"`).
- **`clipboard`** — то же самое, что на Linux.

Третьего режима, `tabby`, больше нет — почему, разобрано во врезке «Почему не Tabby»
выше. Строка `open-mode=tabby`, оставшаяся в старом `tray.conf`, теперь ровно такой же
мусор, как любое другое незнакомое значение: предупреждение в stderr и `terminal`.

Терминальные режимы (все, кроме `clipboard`) действуют только на встроенный бэкенд —
Konsole на Linux, `Terminal.app` на маке (там он и так один); если задан
`--terminal`/`terminal=` (свой шаблон терминала), различие между ними пропадает — шаблон
и так уже победил выбор бэкенда, и все они означают просто «открывай терминалом». В меню
трея они в таком случае остаются кликабельными (иначе из `clipboard` не было бы пути
назад — только правкой `tray.conf` руками), а оговорка написана прямо в заголовке
подменю. `clipboard` — исключение из правила «шаблон побеждает»: он не про то, каким
терминалом открывать, а про то, что открывать не надо вовсе, поэтому работает и поверх
`terminal=`, и на любой платформе.

#### Переключатель «Open in» в меню трея

Тот же выбор доступен без флагов и перезапуска — подменю **«Open in»** в меню трея,
взаимоисключающие пункты с отметкой на текущем. Пункты — те же режимы платформы, из того
же списка, которым проверяется `open-mode=` (`AppConfig::openModes`), так что меню
физически не может предложить режим, который следующий старт трея отвергнет:

```
  Linux                        macOS
  Open in  ▸ ● Automatic       Open in  ▸ ● Terminal.app
             ○ Tab                        ○ Clipboard
             ○ Window
             ○ Clipboard
```

- **Действует сразу.** Следующий клик по сессии открывает её уже по-новому: трей
  пересобирает бэкенд терминала на месте, перезапуск не нужен. Заодно сбрасывается
  счётчик «объяснили один раз за прогон» из режима `tab` — тот, кто только что осознанно
  выбрал «Tab», обязан снова увидеть, почему вкладки всё равно нет, пока
  `EnableSecuritySensitiveDBusAPI` выключен; молчание в ответ на явный выбор читалось бы
  как «сделано».
- **Переживает перезапуск.** Выбор пишется в `~/.config/hgs/tray.conf` строкой
  `open-mode=…`. Файл правится построчно: чужие ключи, комментарии, пустые строки и их
  порядок сохраняются дословно, переписывается ровно одна строка (или дописывается в
  конец, если её не было). Файла не было — он создаётся с короткой шапкой, объясняющей,
  что это за файл и кто его создал. Запись атомарная (временный файл рядом + `rename`),
  так что убитый посреди записи трей не оставит обрезанный конфиг; от одновременной
  правки того же файла в открытом редакторе это не защищает и не пытается —
  на однопользовательском десктопе цена промаха здесь одна строка `open-mode=`.
- **Флаг и меню.** `--open-mode` сильнее файла **при старте** — это не меняется. Но
  выбор из меню — более поздняя явная команда, поэтому он перекрывает флаг до конца
  этого прогона (иначе пункт меню молча ничего бы не делал) и всё равно записывается в
  `tray.conf`. Следующий запуск с тем же флагом в командной строке снова возьмёт флаг.

### `clipboard`: клик копирует команду, а не открывает терминал

Режим, который обходит компромисс обеих платформ сразу. На Linux Konsole не отдаст
вкладку, пока не включён `EnableSecuritySensitiveDBusAPI` (то есть пока право печатать в
твои вкладки не получит любой процесс на сессионной шине, см. ниже). На маке `Terminal.app`
вкладку не умеет в принципе, а единственный кандидат, который умел бы, — Tabby — на маке
недоступен и из трея удалён (см. «Почему не Tabby»). Вставка в уже открытую вкладку не
требует ни того, ни другого — поэтому `clipboard` и единственный режим, одинаковый на
обеих платформах.

- **Что копируется.** Ровно та строка, которую иначе выполнил бы терминал: `hgs a
  <имя>` для своего бокса, `hgs @<alias> a <имя>` для пира. В **New session** внешний
  терминал запускается только с галочкой **Open terminal window**; режим `clipboard`
  относится к открытию существующих сессий. Ничего лишнего, никакого перевода строки в конце — вставка
  ничего не запускает, пока ты сам не нажмёшь Enter. Если задан `--hgs`/`hgs=`, в строке
  стоит именно этот путь, а не голое `hgs`: копируется ровно та команда, которую трей
  выполнил бы сам, с тем самым бинарём, с которым он и разговаривает.
- **Подтверждение.** Балун `hgs-tray: copied to the clipboard` с самой командой в
  теле — на **каждый** клик, а не один раз за прогон: клик в этом режиме больше ничем не
  отзывается (окно не появляется, вкладка не мигает), и без уведомления «скопировалось»
  не отличить от «трей меня не услышал». Команда длиннее 120 символов сокращается
  многоточием **в середине**: и голова (`hgs @mac a`, то есть на каком боксе сессия), и
  хвост (имя сессии, то есть какая именно) — то, ради чего балун вообще читают.
- **Как пишется буфер.** Три способа по очереди: `org.kde.klipper` по D-Bus → `wl-copy`
  → `QClipboard`. Порядок не случаен: на Wayland захватить буфер может только клиент,
  предъявивший serial от недавнего ввода **в свою поверхность**, а у трея своей
  поверхности нет вовсе — меню рисует `plasmashell` по протоколу DBusMenu (тот же корень,
  из-за которого не работает подъём чужого окна). klipper живёт внутри `plasmashell`, и
  serial у него свой. `wl-copy` — для Wayland без Plasma (sway, Hyprland), `QClipboard` —
  для X11 и для мака, где ограничений нет.
- **`wl-copy` остаётся жить — так и надо.** На Wayland содержимое буфера отдаёт
  процесс-владелец, поэтому `wl-copy` форкает демона и держит его до тех пор, пока буфер
  не заберёт кто-то другой. Копий это не плодит: следующий владелец (наш же следующий
  `wl-copy`, klipper, любое окно с Ctrl+C) забирает selection, и прошлый `wl-copy` выходит
  сам — в системе всегда не больше одного. Прибивать его самим нельзя: это стёрло бы то,
  что только что скопировали.
- **Команда с переводом строки не копируется вовсе.** Трей таких не строит, но если бы
  построил — вставленная в оболочку, она бы сразу **выполнилась**, возможно, поверх
  работающего в той вкладке агента. Весь смысл режима в том, что решение «выполнять»
  остаётся за тобой, поэтому такая команда отклоняется с объяснением, а не молча чистится
  (в буфере оказалось бы не то, что показано в уведомлении).

**Чем платишь за `EnableSecuritySensitiveDBusAPI=true`.** Это системная настройка
Konsole, не персональная для трея: включив её, ты открываешь `runCommand`/`sendText`
по D-Bus **для любого процесса на сессионной шине**, а не только для hgs-tray — сессионная
шина общая для всех приложений твоего пользователя. Любой такой процесс сможет напечатать
команду в любую твою открытую вкладку Konsole ровно так же, как это делает hgs-tray. Если
это неприемлемо — держи `window`, `clipboard` (вкладка получится, а включать ничего не
надо) или живи с `auto`, как было.

Второе: **подъём уже открытого окна на этой машине не работает** — на Wayland
xdg-activation выдаёт токен активации только клиенту с недавним вводом, а у иконки трея
своего окна и ввода нет. Клик по уже приаттаченной сессии поэтому не поднимает её окно
наверх, а открывает второй клиент tmux на тот же экран. Ветка подъёма не выключена
намертво в коде — она проверяется заново при каждом клике (`canRaise()`/`raiseTty()` в
`src/KonsoleBackend.cpp`), так что если это когда-нибудь заработает само (другой
композитор, другая версия Konsole/KWin), трей начнёт этим пользоваться без правки кода.

### Официальный DeepSeek Harness

Zerus 0.17 / HGS 1.26 поддерживает **`@deepseek-ai/dsh@0.2.0-rc.2`** — официальный
релиз в npm-теге `latest` на 4 октября 2026 года. В **New session** выберите
**DeepSeek Harness**, машину, папку и группу. Сессия запускается внутри Zerus и
открывается в Activity; ошибка остаётся в окне. Запуск не требует внешнего терминала.
Каталог `~/.npm-global/bin` доступен CLI также из systemd/launchd и через SSH.
Новая сессия ждёт первого сообщения: само создание не запускает задачу. Пустая
Activity предлагает отправить запрос из нижнего поля. Подключение `deepseek-official`
использует API-ключ независимо от входа в аккаунт; для `deepseek-account` без входа
Zerus показывает **Sign in** с кнопкой родного UI и сохраняет черновик до авторизации.
Установка на машине агента:

```bash
npm install -g @deepseek-ai/dsh@0.2.0-rc.2
hgs account login native-dsh
hgs dsh /path/to/project --new -n work
```

Это родной движок DeepSeek с его инструментами, правилами доступа и историей.
HGS запускает отдельный профиль `hgs` официального web-host через штатный `--patch`;
логин и секреты остаются в `DSH_HOME`. Небольшой версионированный адаптер связывает
локальный Session Controller с Zerus через приватный Unix socket.
Веб-интерфейс доступен только на loopback, для удалённой машины используется SSH.
Начиная с Zerus 0.18 / HGS 1.27, рядом с **Activity** у DeepSeek есть вкладка
**Native UI**: официальный интерфейс dsh встроен в окно вместо терминала.
Он открывает рабочее пространство машины со своим списком сессий; сессии,
созданные через Zerus, также добавляются в этот список. Переключение сессий Zerus
сохраняет открытый родной экран и его черновик. Кнопка в заголовке по-прежнему
позволяет открыть UI в отдельном браузере.
Вопросы и подтверждения сессий, которыми управляет Zerus, остаются доступны в
Activity; при ожидании ответа вкладка показывает кнопку **Respond in Activity**.
Авторизация выполняется штатным стартовым URL с cookie-обменом; порт и SSH-туннель
определяются автоматически. Cookies и cache встроенного браузера хранятся только
в памяти. Для сборки требуется Qt WebEngine (`qt6-webengine` на Arch,
`qtwebengine` из Homebrew на Mac). CLI `hgs native-ui <session> --json` возвращает
приватный URL подключения вместо запуска браузера; его вывод содержит токен.

В Zerus доступны Activity, создание, сообщения и изображения, отправка во время
работы, вопросы и подтверждения, модель/effort для конкретной сессии, pause/resume,
переименование, цели, todo и просмотр дочерних сессий. Повтор запроса отправки с тем
же ID не добавляет сообщение снова. При неопределённом результате доставки HGS
предлагает проверить Activity. Смена модели не меняет default профиля, а остановка
сессии не завершает соседних агентов или общий host. Закрытие Zerus оставляет host
работать. **Forget** убирает привязку HGS, сохраняя родную историю.
На Linux с пользовательским systemd фоновой host запускается в отдельном scope,
чтобы перезапуск сервиса Zerus не остановил движок dsh вместе с окном.

Первый адаптер закреплён за указанной версией dsh. Native fork, глобальный поиск по
истории DeepSeek, управление расписанием и перенос его аккаунта между машинами
пока выполняются в родном UI. Для другой версии потребуется проверка контракта;
HGS не перезапускает действующие host/агенты автоматически ради обновления.

Проверка адаптера: `python3 tests/test_dsh_native.py -v` после `cargo build`.
Тесты запускают официальный движок с локальной тестовой моделью без ключей и запросов
к платному API, проверяя историю, lifecycle, вопросы, настройки и браузерный вход.

## Процессы, запущенные агентами

С HGS 1.44 / Zerus 0.34 **Processes** — опциональная вкладка рядом с **Activity**
и **Terminal** (для DeepSeek — **Native UI**). Она **выключена по умолчанию**;
включение находится в **Settings → Processes → Enable Processes tab**.
При выключении вкладка скрыта, её список, счётчик и вывод не опрашиваются.
Эта настройка локальна для каждого Zerus; обычное обновление Activity,
обзора сессий и лимитов продолжает работать независимо.

Сверху — **Live shells / processes**: живые оболочки и отдельные деревья команд,
включая постоянные shell, которые агенты показывают в терминале. Ниже — записи
вызовов инструментов; завершённая история свёрнута. Запись вызова и живое дерево
ОС показаны раздельно: одинаковый текст не доказывает, что это одна задача.
Показаны команда, владелец, состояние, длительность и, когда доступны,
рабочая папка, прогресс и сохранённый вывод. Для живого дерева ОС показаны PID
и число дочерних процессов; отдельный захват его stdout не производится.
Выбор и положение чтения сохраняются при переключении вкладок и сессий.
**Copy command** копирует команду, **View process** в Activity открывает точную
запись инструмента. Счётчик вкладки показывает максимум подтверждённых активных
записей и живых деревьев ОС, без суммирования этих пересекающихся источников.
**Unconfirmed** в счётчик не входит.

| Агент | Источник наблюдения и вывода | Управление |
|---|---|---|
| Claude | Hooks, Bash/tool_result, backgroundTaskId и сообщённые агентом файлы вывода | Stop selected для проверенных живых деревьев ОС |
| Codex | Hooks и CommandExecution в rollout, включая команды code-mode, function_call/output и write_stdin | Stop selected для проверенных живых деревьев ОС |
| Kimi | Hooks, реестр process-задач основной сессии и подагентов, tasks/<id>/output.log | Stop selected для проверенных живых деревьев ОС |
| DeepSeek | tools/execute и ctx.jobs в native bridge | Stop selected для принадлежащих этой сессии native jobs |

Обнаружение деревьев ОС общее для PTY-агентов, без отдельной реализации для
каждого провайдера: отслеживаются дочерние оболочки и самостоятельные группы
команд проверенного процесса агента. Служебные процессы самого Codex/HGS не
предлагаются для остановки. Команда читается из ОС, а не разбирается из текста
терминала. Это не полный диспетчер всех процессов машины.

Список ограничен 128 наблюдениями; история читается ограниченным окном. Это
не обещание полного списка всех когда-либо запущенных OS-процессов. Полные логи
не передаются с fleet poll: при выборе команды читается хвост до 32 KiB;
манифест hooks хранит до 4 KiB. Усечение явно отмечается. Чтение DeepSeek через
`readAt` не сдвигает курсор `read`, которым пользуется модель. Вывод отображается
обычным текстом, без исполнения escape-последовательностей или HTML.

Две одинаковые команды с разными родными ID остаются разными процессами.
Сопоставление по тексту команды не используется. Kimi task-файлы старых версий
могут не содержать родительский tool-call ID: при наличии реестра для владельца
он заменяет строки hooks, чтобы не показывать одну работу дважды.

Завершение ответа агента не завершает фоновые процессы. Сохранённое `running`
без подтверждения живости превращается в **Unconfirmed** с последним известным
состоянием. Для Kimi проверяются принадлежность PID текущему агенту и время
создания процесса; Codex process ID не считается OS PID. Нет выдуманного
процента выполнения, определения «завис» по тишине или автоматических запросов
к модели. CPU/RAM и интерактивный stdin пока не реализованы.

**Stop selected (N)** останавливает выбранные строки: Ctrl/Cmd для отдельных
команд, Shift для диапазона. Выделение сохраняется при обновлении списка.
Правый клик открывает **Terminate** / **Terminate selected (N)** с теми же проверками.
Клик по выделенной строке сохраняет весь выбор; по другой — выбирает только её.
Кнопка доступна, если каждый выбранный процесс поддерживает точечную остановку;
для неподтверждённых, завершённых или неподдерживаемых задач она объясняет
ограничение в подсказке. Запросы идут последовательно, без автоматических повторов.
Смена сессии/conversation/host generation отменяет ещё не отправленные запросы.
Каждый запрос повторно проверяет HGS run/conversation и принадлежность задачи.
Для DeepSeek дополнительно проверяются native host generation, владелец и job ID,
после чего запрашивается родная отмена. Для дерева ОС проверяются родство, PID
и время создания каждого процесса; потом посылается TERM, через 2 секунды при
необходимости KILL. На Linux используются PID handles, на macOS — повторная
проверка точного времени создания. Агент и соседние деревья не останавливаются. **Stopping** сохраняется до
подтверждения завершения. Старый запрос после переподключения или перезапуска
host не может остановить новую задачу с повторно использованным ID. Если машина
недоступна, сохранённые строки становятся неподтверждёнными, управление отключается.
Прерывание всей сессии в Activity остаётся отдельным действием.

Уже работающий DeepSeek host не перезапускается ради обновления. До его обычного
перезапуска доступны записи истории; live registry и Stop selected появляются
у host, запущенного с новым bridge. Сам перезапуск Zerus не перезапускает команды.

CLI для машины-владельца: `hgs processes SESSION --json`.
Явное чтение: `hgs processes SESSION --output ID --run RUN --conversation CONVERSATION`;
для native job DeepSeek добавляется `--generation GENERATION`. Остановка использует
`--stop ID` с теми же проверками. Архив поддерживает `--archive ID` только для чтения.
Команды доступны удалённо через обычный `hgs @machine …`.

В **Settings → Processes** доступны интервалы (по умолчанию): открытая вкладка —
**2,5 с**, фоновые обновления списка/счётчика — **30 с**, вывод Unconfirmed —
**10 с**, задержка индикатора загрузки — **0,5 с**. Детальный опрос идёт **только
для выбранной сессии**, пока открыт её экран и видно окно Zerus. Для невыбранных
сессий, Dashboard, Settings и скрытого окна такого опроса нет. При выключенной
функции Activity использует `hgs inspect --skip-processes`; CLI `hgs processes`
остаётся доступен по явному запросу. Фоновый интервал также ограничивает
обновление состояния выбранной сессии при открытом Terminal/Native UI.

Вывод читается только в видимой вкладке Processes, только для выбранной команды.
Открытие вкладки обновляет данные сразу. Завершённый вывод повторно читается
при изменении статуса/вывода; служебные timestamps чтение не запускают.
Параллельные одинаковые запросы не создаются. Опрос читает локальные данные/ОС
или native registry, на другой машине использует SSH; модель не вызывается
и токены не расходуются. Уже отправленный запрос может завершиться после
выключения вкладки, но не запускает дальнейших опросов.

Утерянный foreground hook не остаётся Starting во время другой команды:
без текущего подтверждения он становится Unconfirmed. Для Codex точные
CommandExecution completion за пределами обычного окна 8 MiB восстанавливаются
инкрементальным чтением до 16 MiB за опрос; результат и позиция чтения сохраняются
в приватном локальном кеше process-history. Даже в большой истории повторный
опрос не сканирует файл заново. Завершение принимается только для точного call ID
в проверенной conversation; отсутствие события не считается завершением.

Проверки: Rust-тесты `state::processes`, lifecycle hooks на приватном tmux,
`tests/test_dsh_native.py` с официальным keyless harness и Qt `processview` /
`sessionswindow` / `activityview`. Они проверяют одинаковые команды, background
после ответа, ошибки, устаревшие identities, раздельный output cursor, точечную
остановку, изоляцию владельцев, смену conversation, offline и сохранение чтения.
