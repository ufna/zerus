Сначала папка.
Worktree — по необходимости.

Агент может работать с документами, конфигами или кодом в любой доступной папке. Git и отдельная рабочая копия дополняют этот сценарий, когда они нужны.

Реализовано в Zerus 0.32.0 и HGS 1.42.0. Уже есть логические проекты, папки на разных машинах, выбор аккаунта и запуск в произвольной папке. Уже определяется Git-контекст сессии.

Каталог worktree находится в отдельной вкладке Worktrees и в Projects. При запуске можно выбрать существующую копию или явно создать новую через New worktree… с новой веткой, исходным ref и путём на выбранной машине. Удаление остаётся будущим этапом. Это интерактивный макет: кнопки меняют примеры на странице, реальные файлы и агенты не затрагиваются.

Обычная папка

Выбрать папку и запустить агента. Репозиторий, ветка и Git на машине не требуются со стороны Zerus.

Основной checkout

Работать в существующем репозитории как обычно. Создавать отдельный worktree для сессии необязательно.

Linked worktree

Выбрать отдельную рабочую копию, когда хочется разнести изменения параллельных задач по папкам.

Как связаны сущности

Проект ZerusНазвание, цвет, список папок и сессий. Может объединять разные репозитории и папки без Git на Arch и Mac. Каждая сессия принадлежит одному проекту. Проект по умолчанию принимает внешние сессии; Inbox — пример такого проекта.
Папка проектаСтабильный ID, машина, путь и необязательное название. Одна физическая папка может входить в несколько проектов. Добавление папки не создаёт репозиторий.
Сессия агентаКонкретный агент, аккаунт на выбранной машине и рабочая папка. Перенос сессии в другой проект меняет её организацию в Zerus, сохраняя процесс, папку и ветку.
Git-контекстНеобязательные сведения о папке: репозиторий, ветка, основной checkout или linked worktree. У папки без Git этих полей нет; это обычное рабочее состояние.

Проекты и их порядок сейчас сохраняются на устройстве с Zerus. Этот дизайн не добавляет синхронизацию организации проектов между Arch и Mac. Каталог аккаунтов остаётся аккаунто-центричным: для запуска используется профиль выбранного аккаунта на выбранной машине.

Запуск сессии

Обычный путь по умолчанию

Проект → машина → рабочая папка → агент и аккаунт → запуск. В поле папки — сохранённые папки проекта и результат Browse. Локально используется системный выбор папки, удалённо — браузер по SSH.

Папка без Git и основной checkout запускаются этим же способом. Zerus не делает git init, не создаёт ветку и не переносит файлы. Новая папка добавляется в проект после подтверждённого запуска, как сейчас; отмена и ошибка ничего не добавляют.

Необязательный выбор worktree

Если папка относится к Git-репозиторию, рядом доступно «Другие worktree…». Выбор существующей копии меняет рабочую папку будущей сессии и оставляет выбранные проект, машину и аккаунт.

Обычный Browse также позволяет сразу выбрать linked worktree. Ни выбор модели, ни отправка сообщений, ни отображение Activity не зависят от наличия Git.

Что действительно проверяем

Машина доступна, папка существует и доступна для работы, агент установлен, аккаунт доступен на этой машине, имя сессии допустимо. Собственные требования и запросы доверия провайдера сохраняются.

Отсутствие Git или ошибка чтения Git-метаданных не блокируют запуск в доступной папке. Для выбора соседнего worktree нужна подтверждённая запись каталога. Запуск в недоступной или удалённой папке запрещён. Запись bare-репозитория в каталоге не предлагается как рабочая копия.

Что показывает New session

Выбранная папка остаётся в самом поле выбора. Ниже — полный путь и принадлежность проекту. Для обычной папки не нужны пустая строка ветки, предупреждение или предложение инициализировать Git.

В макете можно выбрать папку с недоступными Git-данными: кнопка запуска остаётся доступной. Offline отключает запуск и объясняет причину.

Где виден каталог

Sessions и Worktrees

В строке сессии — папка или репозиторий, ветка при наличии, машина и компактная пометка linked worktree. Все основные сессии выровнены одинаково. Разворачивание подагентов остаётся отдельным действием.

В отдельной вкладке Worktrees всегда есть рабочая папка, полный путь и связанные сессии. При наличии Git добавляется список рабочих копий этого репозитория, в том числе пустых. Клик по копии фильтрует список, сохраняя открытую беседу. Явный выбор сессии открывает её; «Все сессии» снимает фильтры.

Projects

Выбранный логический проект → его папки с метками машин. В карточке Git-папки можно раскрыть соседние worktree её репозитория. Они не добавляются автоматически в проект: это обнаруженные места работы, доступные для выбора.

Карточка папки без Git показывает саму папку и связанные сессии. Machines отвечает за подключение и настройку компьютеров. Каталог проектов не превращается в дерево «машина → репозиторий → проект».

Если агенты используют одну рабочую копию, показываем число сессий с общими файлами. Для папки без Git показываем сессии в той же подтверждённой папке. Это информация о совместной работе, а не доказательство конфликта. Подагент без собственного cwd не становится отдельным worktree.

Отдельно позжеРучная очистка, перенос изменений, merge и другие операции Git. Закрытие Zerus, остановка или архивирование сессии не удаляют папку, worktree или ветку. Удаление потребует явного подтверждения, повторной проверки изменений и всех зависимых сессий, включая паузу. Основной checkout, locked-копии, несохранённые изменения и живые процессы защищены. Удаление ветки — отдельный выбор.
Контракт данных и особые состояния
  1. Базовая сущность — папка на машине. Стабильный ID папки проекта хранится в организации Zerus. Обнаружение фактического cwd и Git-контекста выполняется на машине агента. Связь сессии с проектом не вычисляется из Git remote, имени ветки или basename.
  2. Состояния Git различаются: not_repo означает обычную папку; отсутствие исполняемого Git, timeout, права и временная недоступность метаданных обозначаются отдельно. Это не ошибка запуска агента, если сама папка доступна. Нельзя выдавать неудачное чтение за успешный пустой каталог.
  3. Репозиторий: машина + canonical git common directory. Worktree: репозиторий + canonical root. Независимые клоны и одинаковые пути на разных машинах не смешиваются. Cwd внутри подпапки определяется через Git-discovery; сравнения строковых префиксов недостаточно.
  4. API: каталог для известной папки: hgs worktrees --path /absolute/folder --json; удалённая машина задаётся через @host. Данные из git worktree list --porcelain -z: root, common_dir, branch, head, main/linked/bare, detached, locked, prunable, availability, sampled_at. Связанные сессии сопоставляются в Zerus с каноническими путями из снимка той же машины. Аргументы передаются без shell-интерполяции; ограничиваются время и размер ответа. Частичный результат помечается явно.
  5. Обновление по потребности: при открытии Worktrees/Projects, явном обновлении и выборе папки/репозитория; кэш и объединение запросов на один репозиторий. Нет fetch, обхода файлов, полного Git status или каталога worktree на каждом тике списка. Для папки без Git каталог worktree не запрашивается.
  6. Offline: последнее наблюдение с машиной и временем, действия запуска отключены. Старый Working не показывается как текущий прогресс. Поздний ответ другой машины или сессии не меняет открытую карточку, выбранную папку и черновик.
  7. Detached / bare / locked: короткий SHA вместо ветки; bare не имеет рабочей папки; locked показывает причину и защищён от удаления. Missing / prunable остаются видны как недоступные, без автоматического удаления из Git.
  8. Symlink, submodule, Unicode, пробелы и одинаковые названия: определение через Git и canonical paths на нужной машине, полный путь для различения. После перемещения worktree путь обновляется при следующем снимке; принадлежность сессии проекту сохраняется.

Критерии готовности

  • Агент запускается в доступной папке без .git, в основном checkout и в существующем linked worktree на Arch и Mac, локально и по SSH. Zerus не навязывает создание ветки или установку Git.
  • Отсутствие Git и ошибка его метаданных не ломают выбор папки, аккаунта, запуск, Activity, отправку сообщений или обычные действия с сессией; ограничения самого провайдера видны отдельно.
  • Проект объединяет обычные папки и Git-копии с разных машин. Одна папка может входить в несколько проектов; у сессии остаётся ровно один проект. Выбор соседнего worktree не переносит существующую сессию.
  • После Browse папка видна в поле. Выбор worktree сохраняет проект, машину и аккаунт. Отмена, ошибка запуска и чтение каталога не добавляют папку в проект и не меняют файлы.
  • Фильтры папок/worktree сочетаются с машиной и поиском. Пустые копии доступны для обзора, недоступные — помечены. Обновления сохраняют открытый разговор, прокрутку, фокус и черновик.
Папка — обязательный контекст работы агента. Git и worktree — необязательные возможности. Дизайн дополняет нынешнюю модель проектов Zerus.
